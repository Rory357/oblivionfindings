### Run 2 — C1 payroll CSV injection guard (2026-07-10, D-6) + incidental TZ-flake fix
Mapped first: the `SanitizesCsvOutput` trait is mounted on the base **Controller**, so every controller inherits `putCsv`/`streamSanitizedCsv`/`sanitizeCsvCell` — but both payroll CSV paths build their output inside **services**, where nothing inherited applies: `PayrollExportService::buildCsvFromRows`→`encodeCsvRow` (profile-driven run export — encloses + doubles the enclosure char but never neutralises a formula-leading cell) and `PayrollJournalService::buildNetPayDirectCreditCsv` (hand-concatenated bank batch — strips commas only). Employee names are user-chosen and static profile mapping values are free-text → real OWASP CSV-injection vectors on both. No payslip CSV exists (payslips are PDF). Fix: `use SanitizesCsvOutput;` on both services (collision-checked: neither declares `sanitizeCsvCell`/`putCsv`/`streamSanitizedCsv`), sanitise each cell in `encodeCsvRow`, and sanitise `$name`/`$bankAccount` in the direct-credit builder; purely numeric cells stay exact (negative amounts, bank imports). New `tests/Feature/Hr/PayrollCsvInjectionGuardTest.php` (2 tests, 8 assertions): isolated ✅.

**Incidental find (fixed same slice, per the fix-incidentals rule):** the first full-suite gate came back 724/1 — `ShiftPayrollBackboneIntegrationTest` "attendance generated shift timesheet flows into payroll run" failed with a null run item, and kept failing in isolation. Investigated rather than dismissed: my diff only touches CSV cell encoding (item generation untouched), and a stash-to-HEAD experiment + source read found the real cause — a **morning-only timezone flake in the test itself**. `DraftTimesheetService:86` stamps `work_date` as the WORKER-LOCAL calendar day (`app.worker_timezone` = Pacific/Auckland), while the test built its payroll window from raw UTC `now()`. Between 00:00 and ~12:00 NZT the NZ date is a day ahead of UTC, so the fresh timesheet's `work_date` fell past `periodEnd` and the item was never generated. Every prior green run happened NZ afternoon/evening; today's runs were NZ morning (~08:00–09:00 NZST). The sibling test in the same file sets `work_date` directly in UTC (self-consistent — never flaked), and `PayrollRunIntegrityTest`/`AuditFixPayrollCasesTest` likewise. Fix: build the run window from `now()->setTimezone(app.worker_timezone)` in the affected test (mirrors the product's own date derivation); repaired test passes at 09:06 NZST — inside the window where the old one reliably failed. Product code is unaffected (real payroll runs receive explicit picker dates).

**Gates:** php -l ✅ ×4 (2 services + 2 test files) · new test isolated ✅ 2/8 · repaired backbone test ✅ 2/38 at the failing hour · full HR pest ✅ **725 passed / 0 failed** = 723 + 2 new (repaired test back green), zero regressions. **New baseline: 725.** Frontend gates N/A (no .ts/.tsx).
