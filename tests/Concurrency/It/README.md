# Isolated IT concurrency verification

Run this target explicitly from the repository root in PowerShell:

```powershell
& 'docs/audits/2026-09-08-it-support/evidence/run-isolated-it-tests.ps1' -TestPaths tests/Concurrency/It/ItTicketCommandConcurrencyTest.php
```

Run only this file in that process. It is intentionally outside the normal PHPUnit suites and Pest's `RefreshDatabase` scopes. The existing wrapper first proves notification and database isolation, then `Tests\TestCase` creates a fresh randomized local schema, imports the schema dump, applies pending migrations, and registers cleanup of that schema at process shutdown. The working database is never a target. The class rejects execution without the wrapper's exact database base, random token and loopback host before database preparation.

This one test owns naturally committed fixtures for its entire dedicated schema. It never commits a transaction belonging to another test. Two guarded PHP workers join the parent's exact schema and invoke canonical services while the parent holds the relevant actor or ticket lock. Ready and attempt barriers, running-process assertions and timestamps verify that both calls overlap before the lock is released. The workers never run migrations or delete databases. Both processes are stopped in `finally` on failure, and only this run's barrier files are removed.

The creation round expects one canonical ticket, one command receipt, one creation activity/audit and one durable requester notification intent. Both workers must receive the same ticket, with one replay. The edit round expects one committed property change and one stale-version conflict, with one property activity/audit and matching current versions. Notifications are faked and mail, queues and broadcasting retain the wrapper's isolation settings.

Include this explicit target in W27 release verification. Passing the standard suite does not run this concurrency test.
