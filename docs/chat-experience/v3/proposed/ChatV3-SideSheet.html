Why it works this wayC7.3 · one conversation, never the two-pane workspace squeezed into 720 px

Messages keep the sheet

Below the header and above the one-line composer, the messages get 762 of the sheet’s 944 px (81%). Today’s 720 px sheet squeezes the whole two-pane workspace, list and all, into the same space.

MessagesHeader and composer
One conversation, one width

The kit’s 640 px side panel, with the same grouped bubbles, care cards, reactions and composer as the Chat page. The page keeps 564 px beside it. No conversation list: “Open in Chat” goes to the full page with the same conversation, place and draft.

The page underneath still works

No dark overlay. You can scroll and read the profile while you chat. A care card for the page you are on says “Show on this page” and scrolls to it. Other cards open their page under the sheet, and the sheet stays open.

Rules
Esc or ✕ closes the sheet. Your unsent message stays with the conversation, so closing never asks “Discard this draft?”.
It stays open when the page changes through a care card. Moving to another part of Oblivion from the main nav closes it.
A record’s own side panel (for example Edit care plan) and the chat sheet never sit side by side. Chat opens over it; closing Chat shows the panel again with its typing kept.
The sidebar Chat link still opens the full Chat page. The header Chat button lists recent chats; choosing one opens this sheet.
