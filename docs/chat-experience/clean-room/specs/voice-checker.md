# Oblivion voice-note checker: specification

Plan item C2.5. Written 23 October 2026 from Oblivion's own code and the public format specifications: the Matroska and WebM specifications (EBML, RFC 8794), RFC 3533 (Ogg), RFC 7845 (Ogg Opus), RFC 6716 (Opus) and the ISO base media file format (MP4) as published for AAC audio. It makes ffprobe optional for chat voice notes. Builders follow [../README.md](../README.md): do not open the source of FFmpeg, ffprobe, mediainfo, music-metadata, mp4box or any other media parser.

## 1. What it must decide

`App\Services\Chat\ChatVoiceInspector::inspect(string $serverPath): ChatVoiceInspection` keeps its signature and results. The new checker answers the same questions ffprobe answers today (`analyse()` in that class):

- Exactly one stream, and it is audio.
- The container and codec are one of: WebM with Opus (`audio/webm`, what Chrome, Edge and Firefox record), Ogg with Opus or Vorbis (`audio/ogg`), MP4 with AAC (`audio/mp4`, what Safari records).
- The duration, worked out from the audio itself (browser WebM often has no duration in its header), is at least 0.05 seconds and at most 120.5 seconds. Over that is `voice_too_long`.
- The file is 1 byte to 20 MiB.
- Anything else, or anything the parser can't read with certainty, is `blocked` with `voice_file_invalid`. The checker never guesses.

Results: `ready` with the MIME type and `duration_ms` (rounded up), `blocked` with an error code, or `unavailable` only if the file can't be read from disk.

## 2. Reading each format

Read the file through a bounded reader: no read past the end, no element or box larger than the remaining file, at most 1,000,000 elements, boxes or pages per file, and at most 2 seconds of work (stop and block after that).

**WebM / Matroska (EBML).** Variable-length IDs and sizes as RFC 8794 defines; reject an unknown-size element except a Segment or Cluster at the top level. Require an EBML header whose DocType is `webm` or `matroska`. In Segment › Tracks require exactly one TrackEntry, TrackType audio (2) and CodecID `A_OPUS`. Read Segment › Info › TimestampScale (default 1,000,000 ns) and Duration if present. Walk the Clusters: cluster Timestamp plus each SimpleBlock or BlockGroup's relative timestamp gives each block's time, all for track 1. Duration = the latest block time plus its length (taken from the Opus packet's TOC byte, RFC 6716 §3.1: frame size by config, times the frame count) minus the first block time; take the larger of that and the declared Duration.

**Ogg (Opus or Vorbis).** Walk the pages (capture pattern `OggS`, version 0, the header-type flags, granule position, serial number, page sequence, CRC-32 as RFC 3533 defines, which must match). Require one logical stream (one serial number). The first packet identifies the codec: `OpusHead` (RFC 7845 §5.1: version, channel count, pre-skip) or a Vorbis identification header (sample rate). Duration = (last page's granule position minus pre-skip) / 48,000 for Opus, or last granule position / sample rate for Vorbis.

**MP4 (AAC).** Walk the boxes (size, type, 64-bit `largesize`, `size 0` only for the last top-level box). Require `ftyp`, and `moov` with exactly one `trak` whose `mdia/hdlr` handler is `soun` and whose sample entry in `stbl/stsd` is `mp4a`. Read `mdhd` timescale and duration (version 0 or 1), and check against `stts` (sum of sample counts times deltas). Duration = the larger of the two divided by the timescale. Reject `moov` absent (fragmented files without `moov` are not recorded by Safari's MediaRecorder).

## 3. Tests and acceptance

- Fixtures recorded in Chrome, Edge, Firefox and Safari (5 seconds and 119 seconds), generated by the test suite or added as small committed files made by Oblivion, never copied from another project's test data.
- Hand-built files for each rule: two tracks, a video track, wrong codec, too long, too short, truncated in the middle of an element, box or page, a size that runs past the end, a bad Ogg CRC, unknown-size elements, a zero-length file.
- A randomised mutation test (flip and cut bytes of the good fixtures, 10,000 cases) that must never throw out of `inspect()`, never take more than 2 seconds per file and never return `ready` for a file with a broken structure.
- The same results as ffprobe on every good fixture, within 20 ms of duration.
- `voice_notes_available` in the chat policy becomes true without ffprobe installed; with ffprobe configured, both run and a disagreement blocks the file and is reported.

## 4. Removal when it lands

`config/chat.php` `files.voice_probe_binary` becomes optional ("second opinion"). Update Settings › Chat › Service health, `docs/chat-experience/` and the register entry for ffprobe.
