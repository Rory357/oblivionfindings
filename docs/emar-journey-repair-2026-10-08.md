## Findings discovered during implementation and independent re-audit

- Medical forms previously accepted updates without the same Medical read authority and could overwrite unseen data. Direct routes and broad profile edits now require the correct client permissions; restricted edit payloads omit clinical fields and the UI omits those editor steps.
- Profile updates and canonical allergy commands now share row locking so a stale profile save cannot overwrite newer allergy evidence.
- Medical saves use transactional timeline updates and truthful completion feedback. A subsequent notification failure does not turn a committed save into a false failure/retry.
- Medical notifications and later reminders re-check current person/site Medical access before delivery, including forced delivery and older pending notifications.
- Client/profile/shift safety summaries now read canonical allergy entries, severity and review evidence. Hidden Medical data is withheld; an unreviewed empty list does not become “No known allergies”. All four production projection callers were inspected, and shift/risk callers now use explicit Medical and risk-section gates.
- Calendar expiry entries use live positive stock packs after pack tracking starts, excluding quarantined/depleted packs and obsolete legacy expiry dates. Exact pack links preserve medicine, person and house.
- Recovery now checks the original recording receipt without submitting another dose, even when the original PRN/order is no longer eligible. A changed order cannot silently relabel or replace the retained attempt. Witness PINs are removed from retained drafts and must be re-entered.
- The profile header now opens the same medication picker and recorder as the chart; successful recording refreshes the current person's visible chart.
- The first PR review found that reachable round-print buttons still bypassed the required export-purpose step. Both Rounds and Meds today now open the shared purpose/review wizard. The options endpoint resolves the exact authorised round and locks its canonical house/day; unavailable rounds cannot fall back to all rounds. Final export still re-checks access and records the supplied purpose.
- The print-dialog re-audit found a keyboard-focus handoff defect between loading and the wizard. The shared focus-return helpers now retain the original print control; loading cannot restore focus outside the newly opened wizard. The underlying round audit remains mounted, so returning to its print action works.
- A further PR review found that the shared calendar constructed its return link from a browser-only value during server rendering. Both full-page and profile calendar renders reproduced the crash. URL parsing now uses an inert base and Inertia's page URL consistently on the server and browser, preserving the historical week, search and original return context. The focused independent review found no remaining concrete issue.
- The next PR review exposed the same eager browser dependency in the Clinical Summary allergy-management link. A whole-diff independent scan then identified two related inconsistencies: the Shift page initially selected Tasks instead of its requested Medications tab on the server, and Meds today's server-rendered chart link omitted the house/return filters. All three defects were reproduced with actual React server rendering and corrected with Inertia URL state. Meds today still reads live browser query changes, preserving its interactive filters; the Shift tab still falls back when medication permission is absent. Loaded-only profile MAR links retain their live historical date rather than being replaced with stale page state. No other introduced eager page-render crash was found in the whole-diff scan.
- A later review found that receipt recovery still required the original medicine order to be current. The read-only receipt endpoint now resolves the retained original order, including replaced or archived records, and independently re-checks the current person's access, house, module and controlled-medicine permissions. Matching still requires the exact medicine/person/actor/request UUID. Its destination opens the original administration in medication history; no recording permission or write path was broadened.
- The uncertain-result notice now offers a direct saved-result check while the form is open. Switching to the confirmation dialog preserves keyboard focus and the original request identity. The picker identifies an unconfirmed attempt by original medicine, NZ time and outcome, and explains that changing the order does not justify recording the same dose again. Other legitimate medicine choices remain available; the UI does not infer medication equivalence from names or impose a person-wide recording lock.
