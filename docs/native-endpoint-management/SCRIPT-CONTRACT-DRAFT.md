## Immutable reviewed catalogue

Each publication creates a new canonical UUID and immutable revision 1. Catalogue manifest exact fields: script_uuid, script_version, name, publisher_label, sha256, size_bytes, interpreter, interpreter_version, runtime_manifest_sha256, wrapper_sha256, architecture, parameter_schema, execution_policy. Script bytes UTF-8 without BOM, <=262144 bytes. Name/publisher <=200 Unicode scalars, no Cc/Cf. Hashes lowercase SHA256; architecture amd64|arm64. Interpreter is a closed deployment-approved identity, never a browser path. Proposed first identity `powershell7`; exact runtime version and a separately verified complete architecture-specific protected PowerShell 7 bundle are mandatory. Bind its closed file manifest/hash and the fixed wrapper identity, including dependent files; a pwsh.exe hash alone is insufficient. No floating latest version, PATH lookup, runtime download during execution or fallback. Windows PowerShell 5.1 is a separate review decision, not assumed equivalent.

Draft review requires a different currently eligible reviewer from author; publish and withdraw are audited independently. New bytes, runtime, parameters or execution policy require a new UUID and review. Review records privileged side effects, child processes, network destinations, output sensitivity, compensation and restart behavior. Publication is approval to execute reviewed code, not a sandbox or safety proof. Scripts cannot invoke another unpublished script dynamically. Package/runtimes must come from authenticated same-deployment protected staging with locked exact bytes. No browser URLs, filenames, switches, PowerShell fragments, arbitrary modules, credentials or AI-generated executable text.

Parameter schema: <=16 unique ASCII names matching `[A-Za-z][A-Za-z0-9_]{0,31}`; exact per-entry name/type/required/constraints. Closed types boolean, integer (safe JSON integer), string (<=1024 scalars), enum (<=32 bounded strings); no object/array/path/expression/secret type initially. Missing required, extra, null, duplicate or out-of-range input rejects. Canonical values JSON <=8192 UTF-8 bytes. Native validates the published schema and hash again. Parameters travel via a protected private UTF-8 JSON input file read by a fixed reviewed wrapper, never concatenated into command text; wrapper and runtime identity are part of execution policy. No secrets may be supplied until a separately reviewed secret-reference transport exists.

Execution policy exact proposed fields: runtime_seconds(1..900), output_bytes(0..65536 total stdout+stderr), output_retention_hours(1..168), network_mode(reviewed_network), timeout_mode(report_only|terminate_owned_job), success_exit_codes(1..16 uint32 values), expected_observation_schema(nullable approved schema digest). Lead choice: initial publication permits explicitly reviewed-network behavior only. Do not advertise a network-deny mode. A future network-deny policy requires separately implemented and accepted OS enforcement; an instruction inside a script is insufficient. Side-effecting scripts require an independently measured expected observation; exit zero alone means completed execution, not a verified desired state.

No redirects, browser URL or arbitrary fetch. Poll exact `{command:envelope|null,cancellation:envelope|null}`. Envelope uses existing original-byte Ed25519 payload/signature. Closed schemas, duplicate/null/type/invalid Unicode rejection, signed JSON <=32768 bytes, UTC strings exactly yyyy-MM-ddTHH:mm:ssZ. Dispatch <=1 hour; final claim <=30 seconds, never renewed for the same uncertain attempt.

Signed dispatch exact 13 fields: version(1), type(endpoint_script_run), agent_uuid, command_uuid, attempt_uuid, assignment_fingerprint, capability(endpoint.script.run), parameters, policy, technician, purpose, issued_at, expires_at. Parameters exact 4 fields: script_uuid, script_version, manifest, inputs. Manifest is the immutable catalogue shape above; inputs closed canonical typed values. Policy exact 3: version, enabled(true), consent_mode(attended|unattended). Technician <=200 and purpose <=500 Unicode scalars, safe plain text. Payload hash binds all bytes and immutable input intent.

Claim request exact 5 unattended/6 attended: command_uuid, payload_hash, artifact_sha256, runtime_manifest_sha256, boot_id, consent? {desktop_session:UUID,consent_nonce:64lowerhex}. Signed claim exact 16: version(1), type(endpoint_script_claim), agent_uuid, command_uuid, attempt_uuid, assignment_fingerprint, payload_hash, policy_version, consent_mode, artifact_sha256, runtime_manifest_sha256, boot_id, desktop_session(nullable unattended), consent_nonce(nullable unattended), issued_at, expires_at. Verify exact staged script/runtime and current unlocked OS peer/logon session immediately at ResumeThread, plus wall/monotonic lease and shared mutation gate. Claim replay returns identical bytes, not a fresh lease.

Result exact proposed 10: command_uuid, payload_hash, status, mutation_started, reason_code, exit_code(nullable uint32), boot_id, output_sha256(nullable), output_bytes, output_truncated. Status completed|awaiting_observation|failed|uncertain|declined|cancelled|expired. Reason enum completed, exit_failed, timed_out, cancellation_requested, cancelled, declined, expired, artifact_invalid, interpreter_unavailable, input_invalid, policy_unavailable, consent_lost, interrupted, state_unavailable, operation_failed. Before launch false/null exit; claiming crash uncertain/interrupted/false and lost claim reply uncertain/state_unavailable/false; entered crash true. Non-mutating uncertainty grants no retry. Known process exit is completed or failed, with mutation_started=true; desired-state success requires independent observation. Timeout/cancel may remain uncertain, never imply rollback. ACK exact {command_uuid,attempt_uuid,payload_hash,accepted:true}.

Output is private and never part of inventory, heartbeat, consent text or ordinary command summary. Upload exact header {command_uuid,payload_hash,sha256,size_bytes,truncated} plus bounded binary UTF-8 content; one immutable upload per attempt/hash, authenticated current identity and ownership. Encrypt at rest; retrieval requires current technician scope, separate sensitive-output grant and audit. Retention expiration removes content while preserving non-sensitive immutable receipt/hash. No raw output in logs or error messages. Redaction is not a guarantee scripts cannot disclose data: publication and output access are security boundaries.

Heartbeat capability exact {version:1,installed_service:true,release_enabled:true,executor:'reviewed_script'} only when installed SYSTEM/SCM/release/runtime gates actually pass. Optional script observations <=8 bind command_uuid,attempt_uuid,boot_id,observed_at,schema_digest,values; schema-bound closed values <=4096 bytes, no arbitrary raw script output. Exact accepted rows are evidence acknowledgements, never execution grants. Recovery reporting remains current identity/assignment scoped after catalogue/policy/release withdrawal.

## Durable launch, cancellation and timeout

Persist prepared -> claiming BEFORE final HTTP -> entered BEFORE CreateProcess -> suspended child PID+creation time and job identity BEFORE ResumeThread -> running -> terminal. Persist exact inputs and hashes privately. Reload claiming becomes uncertain false; entered/running becomes uncertain true and cannot spawn again. No absent PID assumption. Re-establish shared SCM/restart/software/script exclusion before other workers start. Protected state bounded at 256 entries; acknowledged expired settled entries only can retire with a persisted anti-replay watermark. Outstanding process, uncertainty or observation evidence cannot be silently purged.

Job object assignment precedes resume, no breakaway permissions, fixed working directory and explicit environment, no inherited environment secrets, user credentials or unrelated handles. SYSTEM retains inherent machine identity and privileges; this contract does not claim to remove them. Completion requires owned root exit plus owned job process-tree quiescence, but that is not proof all system effects ended. Job membership does not contain broker/WMI-created work or arbitrary SYSTEM code. Lead choice: reviewed scripts prohibit detached and broker-created work; desired-state and crash/boot recovery require independent postconditions, not job quiet alone; stdout/stderr readers stay bounded and drain safely after limit, setting truncated. Service exit must not silently kill jobs unless that exact reviewed timeout/lifetime policy was agreed; recoverable named protected job and exact process creation identity need installed acceptance. Timeout defaults report_only: retain handles/gate and report timed_out uncertainty while running. Termination requires explicit approved terminate_owned_job policy, applies only exact owned job, cannot undo effects, and is terminal only after quiescence. No blind PID kill, fresh automatic attempt or generic process termination shortcut.

Signed cancellation exact 9 fields: version(1),type(endpoint_script_cancel),agent_uuid,command_uuid,attempt_uuid,assignment_fingerprint,payload_hash,issued_at,expires_at. Before entry, durable cancelled false is possible under the same launch lock. After entry, cancellation_requested is not cancelled; only reviewed owned-job policy may request termination, with truthful uncertain side-effect attribution. Server cancellation prevents fresh final claim. Offline or expired dispatch cannot launch; running child expiry does not cause a new attempt. Unknown result retains immutable UUID and read-only recovery.

## Primary runtime facts

PowerShell execution policy is not a security boundary and NonInteractive does not sandbox privileged code; use reviewed immutable code and OS enforcement, not Bypass as authorization. [Execution policies](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_execution_policies), [PowerShell executable options](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_powershell_exe). Job objects group processes and may enforce limits/termination, but breakaway settings affect descendant membership and termination cannot reverse completed side effects. [Windows job objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects). Suspended creation enables assigning/persisting before execution; it does not eliminate the journal/CreateProcess crash gap. [Process creation flags](https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags). These are runtime facts, not evidence that this draft executor is implemented or safe to release.

Lead runtime choices: provision side-by-side architecture-specific PowerShell 7 from a separately verified protected complete bundle, pin an explicit reviewed release, and bind bundle manifest plus wrapper identity. Microsoft documents ZIP deployment and x64/ARM64 choices: [Installing PowerShell on Windows](https://learn.microsoft.com/en-us/powershell/scripting/install/installing-powershell-on-windows). Microsoft documents job lifetime and the Win32_Process.Create child-membership exception: [Job objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects). These facts require reviewed no-detached/broker behavior and independent observation; jobs are not a SYSTEM security sandbox.

## 21 October 2026 — Per-computer script policy API

`EndpointScriptPolicy` now owns script configuration for canonical computers. Defaults are disabled and attended. Explicit `scriptPolicyManage`, `scriptRun` and `scriptUnattended` permissions are registered without role grants; a catalogue reviewer/upload permission does not confer these permissions. Policy reads use current account approval, mandatory script MFA, approved Site, device visibility and active assignment authority. Saving requires policy management and fresh script identity confirmation. Enabling unattended use additionally requires its own permission, including on exact retries; losing that grant does not prevent an otherwise authorised manager disabling the policy.

The new migration adds an append-only revision/receipt table, with unique device/version and actor/request identities and restrictive ownership references. There is no mutable shadow head. Writes lock current actor and device evidence, compare the expected revision and atomically append the receipt and a minimal device activity event. A reused key with changed intent or another computer conflicts. Exact authorised replay precedes stale-version rejection and returns the original receipt separately from current policy. Recovery requires the original actor's current management access, but does not require renewed identity confirmation because it performs no mutation. Private reasons and assignment fingerprints remain in the scoped receipt; the general activity event contains only actor and revision.

Assignment fingerprints use current locking reads rather than an older repeatable-read snapshot. A changed assignment invalidates the saved policy's application: current policy falls back to disabled/attended while retaining the revision needed for an explicit replacement. Prior-assignment receipts cannot be replayed or recovered through the new assignment. Malformed or inconsistent saved receipt/request evidence conflicts instead of silently replacing history.

The private HTTPS API is under `/security-devices/devices/{device}/endpoint/script-policy`: GET current configuration, PUT a closed JSON save, GET `/requests/{request_key}` for recovery, and GET `/confirm-identity` for step-up. Reads require one exact `expected_actor_id` query value; writes are query-free and reject duplicate JSON keys, incorrect scalar types and unknown fields. Existing remote-support origin/error protection now includes these routes. Errors remain generic and private even with application debugging enabled.

Execution availability remains explicitly false, including when configuration flags are changed. This API does not grant consent, stage an executable, create a command or prove runtime eligibility.
