# SD-05 CCTV live contract — v1

Owner: PHP backend agent. This is the implemented protocol contract, not hardware acceptance. One organisation, approved Sites, canonical Device ownership and current roles/media permission are the boundaries. There is no additional enrolled daemon identity or command queue.

## Supported source and deployment

The initial provider transport is `unifi_cloud_connector_rtsps_v1`: fixed HTTPS origin `https://api.ui.com`, current governed UniFi provider API key, explicitly verified console/Protect-camera mapping, and existing configured low-quality RTSPS. The enrolled Windows/Linux Site collector supervises a bundled Go RTSPS-over-TCP to WebRTC worker through private IPC. No FFmpeg/transcoder, screenshots, microphone, talkback, PTZ or browser data channel. Initial video codec is H264; any other codec fails `unsupported_codec`.

Official documentation describes Cloud Connector console firmware >=5.0.3, Protect meta/info, camera details, and GET/POST camera RTSPS streams. Initial supported Protect schema is the documented 7.3.53 integration-v1 contract, with applicationVersion checked against an explicit supported-version allowlist; additional versions require reviewed contract evidence. References: [Cloud Connector](https://developer.ui.com/protect/v7.3.53/connectorpost), [RTSPS creation](https://developer.ui.com/protect/v7.3.53/post-v1camerasidrtsps-stream), [existing RTSPS streams](https://developer.ui.com/protect/v7.3.60/get-v1camerasidrtsps-stream), [camera identity](https://developer.ui.com/protect/v7.3.68/get-v1camerasid), [application version](https://developer.ui.com/protect/v7.3.68/get-v1metainfo). Official indexed pages were available on 2026-10-08; some direct version-page fetches returned404. Documentation is transport evidence, not deployed-version acceptance.

Only fixed paths under `/v1/connector/consoles/{verifiedConsoleId}/proxy/protect/integration/v1/` are called: `meta/info`, `cameras/{verifiedCameraId}` and `cameras/{verifiedCameraId}/rtsps-stream`. Reuse UnifiTransportSecurity TLS/CA verification and no redirects before attaching credentials; bounded JSON replies/timeouts/rate limits. Viewer Start uses GET existing RTSPS only. Enabling low RTSPS is a distinct audited integration-administrator setup operation using the documented POST body `{qualities:["low"]}`. Viewer stop never deletes a shared vendor stream. Local Protect API is a separately version-evidenced future transport, never a guessed localhost fallback.

Multiple recorders per Site are supported by explicit per-camera source bindings, not a Site-unique recorder column. Binding includes canonical camera/recorder/Site/collector/network IDs, verified console ID and Protect camera ID, revision, current provider/site-config/credential fingerprints, supported application version and approved RTSPS dial/TLS evidence. Protect camera details must verify the reviewed mapping; Site Manager ID or MAC is not treated as a Protect camera ID. Canonical camera and recorder must each resolve to the same single active approved Site. Reassignment, ambiguity, changed provider mapping/credential or source revision ends existing authority.

RTSPS locators and bearer paths remain sealed to the enrolled collector. Source egress, every negotiated RTSP SDP/control target and redirect are pinned to the approved network and exact reviewed IP/port/server-name/certificate fingerprint; relative controls must resolve inside the exact approved source authority, alternate origins/addresses fail closed and credentials cannot cross origins; redirects, hostname rebinding, changed addresses, another recorder or unapproved transports fail closed. No arbitrary browser/observed URL, permissive private-address exception or TLS bypass. Deployment must supply real RTSPS certificate/trust evidence and real collector reachability before enabling readiness.

## Deployment settings

These settings belong to deployment configuration, never browser source inputs. Live viewing remains off by default. Accept the supported Protect version, enrolled persistent media worker, recorder/camera mapping, TLS identity and TURN deployment before enabling it; configuration alone does not establish working camera video.

| Environment key | Default | Meaning |
| --- | --- | --- |
| `CCTV_LIVE_ENABLED` | `false` | Explicit application live-view release gate. |
| `CCTV_LIVE_MAX_SESSION_SECONDS` | `300` | Session lifetime; existing runtime policy bounds it to 60..3600 seconds. Worker authority remains at most 15 seconds. |
| `CCTV_TURN_URLS` | empty | Comma-separated deployment TURN URLs, trimmed; 1..4 endpoints when starting a session. Explicit host and port; TURN UDP/TCP or TURNS TCP. TURNS UDP is unsupported. |
| `CCTV_TURN_REST_SECRET` | absent | Protected server-only TURN REST credential secret, 32..512 bytes. The approved TURN service must use the same secret. Never project or log it; browsers receive only expiring derived credentials. |
| `CCTV_TURN_RELAY_CIDRS` | empty | Comma-separated literal allocation pools, trimmed; 1..8 reviewed CIDRs, IPv4 prefix at least /24 or IPv6 at least /120. These are actual relay allocation addresses, not unrestricted private-network permission. |
| `CCTV_TURN_RELAY_PORT_MIN` | `49152` | Lowest approved relay allocation port, at least 1024. |
| `CCTV_TURN_RELAY_PORT_MAX` | `65535` | Highest approved relay allocation port; at least the minimum, at most 65535, with at most 32768 ports in the range. |

Relay allocation CIDRs and ports must match the TURN server configuration. Missing or invalid relay configuration remains controlled `temporarily_unavailable`; there is no insecure fallback. Numeric settings must parse as whole integers. Refresh Laravel cached configuration through the normal approved deployment procedure after environment changes. Implementation changed no environment file or production settings.

Each offer and answer requires exactly one complete SHA-256 DTLS fingerprint (32 hexadecimal octets). Whole bounded JSON offer/result bodies preserve raw SDP bytes and their signed hash despite form-string trimming; escaped/nested duplicate object keys are rejected.

Canonical CCTV camera cards expose server-derived `live_href` and `setup_href`; Device profiles expose the same under `cctv`. Current actor, canonical Site, media and management permissions govern these links. Link availability does not assert current streaming.

## Browser page and requests

GET `/security-devices/devices/{device}/live` returns Inertia page `security-devices/cctv/live` with:

`{actor_id,camera:{id,name,site:{id,name}},live:{available,reason_code,can_start,source_revision,transport:"webrtc",video_codec:"H264",audio_enabled:false,max_session_seconds:policy_int,lease_seconds:15,start_href,setup_href,setup_ready,streaming:false},recording_references:{state:"not_requested",reference:null}}`.

policy_int is the captured server duration (default300, bounded60..3600), not a fixed five-minute product maximum. setup_ready means a verified source and current collector capability exist; page streaming:false never claims an active session. setup_href is null unless the current actor may configure this camera. No public vendor locator, credentials, dial IP, certificate or provider camera ID. Unavailable source_revision/start_href are null. Hidden/inaccessible camera404; a visible camera without media permission exposes restricted readiness without source details.

POST `/security-devices/devices/{device}/live-sessions` exact body `{expected_actor_id,request_key,source_revision,purpose}`: positive typed actor/revision, UUID request_key, trimmed control-free purpose10..500 Unicode scalars. Start is explicit. Request-key replay is actor/browser/camera/private, immutable exact input; mismatched replay409 and no second session. All JSON success responses are `{actor_id,camera_id,session}`.

Session exact fields:

`{uuid,actor_id,camera_id,negotiation_uuid,generation,status,reason_code,server_now,authority_until,session_expires_at,ice_expires_at,transport:"webrtc",video_codec:"H264",audio_enabled:false,ice_servers,answer,status_href,offer_href,renew_href,stop_href}`.

- UUIDs canonical; negotiation_uuid initially null. generation positive integer, starts1 and increments only for successful renewals.
- status enum `requested|negotiating|ready|stopped|expired|revoked|failed`. ready means a validated worker answer is available, never proof that the browser decoded live frames.
- All times strict UTC `YYYY-MM-DDTHH:mm:ssZ`. Absolute lifetime is captured from bounded server policy at Start (default300s, permitted60..3600s), authority_until<=server_now+15s and<=session_expires_at; no extension of absolute lifetime. Client derives the granted window from strict UTC server_now/authority_until and measures its conservative monotonic deadline from the local request start and closes at the earliest authority/session/TURN deadline.
- ice_expires_at is null before provisioning and otherwise the same strict UTC deadline as TURN material; worker and browser both close by it.
- ice_servers is either[] or one exact `{urls,username,credential,expires_at,relay_cidrs,relay_port_min,relay_port_max}` object: approved TURN/TURNS URLs only, opaque session-specific REST credentials, expiry<=session_expires_at. relay_cidrs is1..8 deployment-owned literal allocation CIDRs (IPv4 prefix>=24/IPv6>=120), and relay_port_min/max explicitly bound allocation ports1024..65535 with range<=32768 ports. A claimed typ=relay is not trusted: central/browser/worker reject candidate literal IP/port outside these exact pools; worker also applies remote IP filtering before ICE. Related raddr/rport are bounded literal metadata only and never authorize another candidate/dial; c=/rtcp targets must be unspecified or inside the same approved relay pool/range. remote-candidates/control targets are rejected. No STUN or host/srflx candidates; immutable TURN material remains bound for the peer lifetime. No silent renewal of expired TURN credentials; new peer/session required.
- answer null or exact `{type:"answer",sdp}`; bounded32768-byte UTF-8 SDP, video-only sendonly H264, relay candidates only.

GET `/security-devices/cctv/live-sessions/{uuid}` is the status_href; expected_actor_id is the only accepted query key. POST sibling `/offer` exact `{expected_actor_id,negotiation_uuid,expected_generation,sdp}`. Browser creates exactly one recvonly video transceiver with relay-only ICE, waits for gathering completion, and posts a complete immutable offer<=32768bytes. No audio/datachannel/control; different SDP/UUID after acceptance409. Matching retry returns current same session/answer. POST `/renew` and `/stop` exact `{expected_actor_id,expected_generation}`. Stop is idempotent for the matching owned session even if its generation has advanced; never renew or disclose a new source through stale stop.

Browser polls status and renews liveness every5s, within authority. Visibility loss/pagehide/unmount/Stop clears video and peer immediately. Any failed authority check/renew or authority deadline closes locally; no optimistic live label. Only fresh decoded frames justify Live; stale frames are blanked. Recovery requires explicit new Start, not automatic session resurrection.

Authority is bound to current actor identity/fingerprint, browser session HMAC, canonical camera/recorder/Site assignments, source revision/configuration/credential revision, selected enrolled collector and negotiated offer/TURN/source hashes. Every status/offer/renew checks current evidence. Source/credential acquisition and external calls occur outside long database locks; reacquire current evidence afterward before revealing a lease/answer. Use AuthorizationEvidenceLockService and canonical access services, without the IT-only ObliStaffAccess gate.

Each choices entry (recorders/collectors/scopes) is `{items,limit:20,next_href,previous_href}`, with item `{id,name}` and scope additionally `{collector_id:null|positive_int}`. Fixed relative next/previous links retain only those validated filters. Changing search/collector discards the previous cursor.

Enable request_key is an actor/camera/action-private immutable receipt. The pending receipt and current actor/source/credential context fingerprint are persisted before the vendor POST. The selected DiscoveryScope is an active existing approved network context for the same Site/collector; source IP must be within its CIDRs and outside exclusions with explicitly permitted port bounds. Validate selected recorder, collector device, cloud Site mapping and source camera all remain current same-Site after I/O before saving the immutable revision and audit. ## Collector central interface

Results body exact `{collector_id,request_key,results}` bounded4 results; response `{accepted:[{session_uuid,generation}]}`. Browser requests are never supplied directly to a provider. Work/result UUID replay is immutable, exact identity/session/generation/negotiation scoped. These ephemeral session operations are not DeviceManagement commands and never enter its queue.

Open operations are `{operation:"open",request_uuid,grant,credential_lease}`; renew is `{operation:"renew",request_uuid,grant}` and close is `{operation:"close",request_uuid,session_uuid,generation}`; expiration and exact signed hashes must match. Worker failure/EOF/authority failure can never extend the grant. Central results recheck current actor/session/source/collector evidence before accepting an answer.

## Signed worker authority and private IPC

Grant exact fields:

`{version:1,type:"collector_cctv_live",collector_uuid,site_id,camera_id,recorder_device_id,provider:"unifi",console_id,provider_camera_id,session_uuid,negotiation_uuid,generation,source_revision,source_sha256,turn_sha256,offer_sha256,quality:"low",video_codec:"H264",audio:false,discovery_scope_id,allowed_ip,allowed_port,tls_server_name,tls_pin,issued_at,expires_at,session_expires_at}`.

Hashes are lowerhexSHA256 of the exact JSON_UNESCAPED_SLASHES/UNICODE UTF-8 bytes of the closed ordered source/turn objects and of raw offer SDP bytes. Session generation starts1. First worker open accepts any current positive generation, because the browser may have renewed during setup; remember that accepted highest generation and the Start-captured immutable absolute deadline. Equal-generation work replay returns the prior exact response without refreshing expiry/watchdog or reopening media. Renewed grants increase generation and preserve all immutable identity/scope/hash fields. Higher-generation open may recover an existing nonterminal peer only with matching immutable identity, source, TURN and offer fields/hashes; it reuses that same peer and answer without another dial. Closed or locally expired session tombstones cannot be reopened. issued_at cannot be future, expires_at<=issued_at+15s, absolute session deadline<=initial issued_at+3600s and equals the immutable policy deadline captured at Start. Validate signature before using any locator or authority; replay cannot restart a closed generation/session.

Private IPC is uint32 big-endian length + closed UTF-8 JSON<=65536bytes. Fixed protected child executable; no secret argv/env/stdout diagnostics. Configure once `{version:1,operation:"configure",collector_uuid,site_id,server_public_key}`. Authority-free health probe is `{version:1,operation:"health",request_uuid}`; health/configure reply uses the standard seven fields with session_uuid:"",generation:0,status:"requested",answer:null,reason_code:null. Health never creates or renews media authority. The persistent lane probes the configured child before each authenticated work poll. Open exact `{version:1,operation:"open",request_uuid,grant,source:{url,username:null,password:null},turn:{urls,username,credential,expires_at,relay_cidrs,relay_port_min,relay_port_max},offer:{type:"offer",sdp}}`. No caller-defined RTSP headers/properties. Renew `{version:1,operation:"renew",request_uuid,grant}`; close `{version:1,operation:"close",request_uuid,session_uuid,generation}`. Signed hashes bind the original private objects.

Reply/event exact `{version:1,request_uuid,session_uuid,generation,status,answer,reason_code}` with same session statuses and nullable bounded answer. ParentEOF closes every peer and source; independent wall-clock plus monotonic watchdog stops before grant expiry even while RTP continues, clock rollback cannot extend authority. Max2 distinct cameras/4 peers per collector,2 sessions per actor, bounded RTP queues with stale packets dropped. Source/peer disconnect never silently restarts after terminal closure. Video-only H264 capability stays unavailable unless the child and persistent supervisor are present and report current readiness.

## Errors, audit and recording references

Browser presentation derives no authorization from these labels.

Audit start/negotiation/stop/expiry/revocation/failure with AuditLogger::logOrFail in the governing transaction, actor, canonical camera/recorder/Site, opaque session/request fingerprints, purpose and safe reason. No video/audio capture or recording by this bridge. Do not store stream locators/TURN credentials/SDP in retained audit rows. Protected transient signalling/source data is erased at end/expiry; immutable access metadata follows the existing application audit retention owner, with no invented automatic audit-deletion horizon.

The page starts not_requested with reference:null. A separate authorized chosen UTC window may produce a reference_only record only when actual verified recorder/camera/time identities are present.
