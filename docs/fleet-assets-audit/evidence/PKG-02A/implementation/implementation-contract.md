### Read contract

The current profile location prop gains a versioned workspace envelope. It includes server check time, client/assignment identifiers, observation identity/time/received time/accuracy/source, independent battery sample time, current collection/viewer decisions, approved action capabilities and exact same-origin action URLs. Recipient sharing is independently known/unknown/unconfigured; omit recipient details for viewers lacking authority. Denied responses include only safe reason codes and permitted next links.

An authenticated no-store workspace refresh endpoint returns this envelope and permitted zone/outings/response summaries. Every child record is resolved through this exact client and site. Lookup endpoints for linked boundaries, workers and outing destinations return only eligible records; a forged ID cannot bypass the same rule at save. No query accepts a client/site/device identity chosen by the browser in place of the route's canonical client.

Latest observation, a selected historical observation, a plan and a staff response remain separate records. Device command acknowledgement never rewrites observation time or battery time. Unknown accuracy renders no implied accuracy circle. No marker, empty alerts, registry status or planned outing claims wellbeing. Responses are private/no-store and precise location/decision details are excluded from URLs and unrestricted logs.

### Zone proposal and scheduling contract

Propose additive client_geofence_rules and immutable client_geofence_rule_versions, referencing the canonical client/site and AssetGeofence plus current authority/assignment identity where relevant. Each version records name, client purpose, agreed/attention classification, schedule, response proposal, canonical geometry identity/hash, actor and revision. Draft shape data is an explicit proposal; operational geometry is canonical AssetGeofence. Never overwrite an existing shared boundary through a client edit.

POST /operations/clients/{client}/location/zones creates a proposal with an actor/operation/payload-aware idempotency key. PUT on an exact owned rule supplies expected revision; stale edits return 409 with a safe reload/review path. Accept either an eligible canonical boundary plus expected geometry hash, or a validated new circle/polygon proposal. Canonical creation/version binding occurs atomically through the approved geometry path. Global geofence reads/writes must respect site and protected client association; no new client-private boundary may leak through an unscoped sibling register. Narrow access corrections on touched canonical consumers are prerequisites, not a whole Sites editor redesign.

The schedule payload uses explicit timezone, ISO weekdays, start/end wall times, explicit following-day flag, first/last calendar dates and explicit exception dates. It contains no implicit all-day, default duration or alert exemption. Validate actual dates, nonzero intervals, overnight consistency, bounds, exception membership and shape topology on the server. Convert/evaluate against authoritative observation time, not browser time. Treat unsupported DST ambiguity/gaps as a configuration/review result until the policy specifies their interpretation. Do not silently normalize ambiguous user-entered instants.

Drafts persist and are visibly inactive. Activation requires an explicit versioned approved rule, current canonical authority, permitted actor and fully specified response/evaluation policy. Expiry/withdrawal/site/device reassignment/geometry mismatch invalidates dependent activation. A field labelled active must correspond to server enforcement; no scheduled-looking UI over an ignored time_rules field. Shared geometry changes require impact review or invalidate dependent rules for review. No backfilled activation of legacy shapes or silent migration from the single house rule.

Extend the existing server telemetry → evaluator → deduplicated signal/outbox → Control Room path only after its configuration contract is approved. Client rules must not be evaluated by the legacy asset evaluator merely by setting AssetGeofence.is_active. Per-rule classification and uncertainty remain explicit; do not invent an any-zone-is-safe precedence. First, delayed, duplicate, inaccurate and out-of-order observations cannot produce fabricated crossings. Directions, confirmation/dwell/hysteresis, overlap, response ownership and DST semantics are explicit versioned configuration with no live synthetic defaults. Evidence includes observation/rule/version/assignment identity, and replay is idempotent. The browser is not an alert scheduler.

### Locate now contract

The dialog displays exact current assignment, reason, genuine identity-confirmation requirement and request status.

A client-scoped adapter validates the route client and current tracking assignment, constructs only tracking.location_refresh with validated empty/approved parameters, and calls the canonical request service using the actual session step-up timestamp and idempotency key. It queues only through DeviceCommandQueueService when governance permits. Awaiting identity/approval/confirmation states remain pending; no preview confirmation bypass. Reopening or retry returns the canonical request. The subsequent status read rechecks client/assignment/authority and filters the command to its requesting context. Provider credentials and raw commands never reach this UI.

Preserve the existing redirect contract for legacy callers; an explicit JSON workspace request can negotiate the new response. Step-up should use the existing password-confirm path and validated same-origin return context. Revalidate after return and before request/execution/delivery. A command ACK is distinct from an observation received after the request, with correlation limitations stated if the provider has no command-linked observation ID. Timeout, unavailable and provider refusal use canonical statuses/configuration, not a new hardcoded timer. Browser polling uses cancellable no-store reads and cannot resurrect an ended assignment. No real unit is polled during QA.
