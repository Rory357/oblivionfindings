## Source checks and bounded first slice

Main independently read ClientController::locationHistory and privacy status, use-personal-location-privacy.ts, FleetGeofenceService, AssetGeofence and FleetOuting, and inspected the existing command request/queue guards. Source supports the principal contract findings:

- History checks current assignment before a generic history read and passes date/retention filters, but the inspected controller has no post-read authority recheck. The first slice must bound history to the exact current assignment/collection interval and reject a changed assignment/authority after reading, rather than relying only on retention dates.
- The shared privacy hook lacks abort/request-generation protection, permits overlapping refreshes and can set active true from a late successful response. Fixing this requires regression for stale success after denial, route/client/assignment change and unmount; it is not sufficient only to clear visible rows once.
- FleetGeofenceService selects is_active asset-associated geometry, evaluates containment and emits enter/breach/dwell signals without applying time_rules. Existing presence in that register is not proof of an active client schedule. Newly saved drafts must not enter that evaluator, create asset assignments or activate canonical geometry as a side effect.
- AssetGeofence is the canonical geometry source; client purpose/schedules and immutable proposals remain separate. The existing eligible-site selector also requires active house/resident scope. Before implementing draft persistence, make the exact draft geometry storage and publication boundary explicit: either keep proposed geometry in protected client rule revisions until canonical approval, or prove every affected canonical consumer protects an inactive client draft. No unscoped Fleet/Site map/list may expose client-private names, geometry or relationships.
- FleetOuting has a driver field but lacks the proposed generic support-worker/planned-arrival fields. Nullable additive extension may preserve canonical ownership; it must not repurpose driver authority or let a single-client adapter modify other participants. Existing Maintenance booking/restriction paths remain binding for optional vehicle-backed actions.
- The command services retain device-view/access validation, governed capability/step-up/idempotency logic and after-commit queued dispatch. Client Location must adapt those contracts, not introduce a direct transport or preview identity bypass. Mock transport and explicit disabled external execution are required in tests.

The proposed first protected read/draft slice does not depend on Maintenance checklist, release authority or named coordinator configuration. Existing-policy history/command presentation, current-access clearing, v3 UI fidelity, inactive zone proposals and non-vehicle outing planning can be developed as incremental approved-scope work after timing/isolation release. This is not a reduced completion scope. New operational rule evaluation/activation and recipient/self-access disclosure remain gated on their actual contracts; PKG-01 A4 is not inherited.
