# Vehicle workspace implementation map

22 September 2026. Working implementation inventory, not a completion claim. Canonical authority is the recorded Main build release and approved frozen v13. Single organisation; permission, approved site, direct object and privacy checks apply to every projection and command.

## Frontend ownership and reuse

Root Astra owns all React and CSS. Replace the existing `resources/js/pages/fleet-assets/vehicles/show.tsx` operations layout with the approved workspace using the existing `PageHeader`, `PageHeaderRail`, `TierTwoTabs`, `WizardShell`, `ReviewCard`, date/time fields, searchable command selectors, semantic status tokens and private upload controls. Preserve the existing separately permissioned vehicle technology projection. No imports from the preview and no demo model/store in application code.

Approved top-level views: Overview; Service & compliance; Checks & inspections; Maintenance; Map; Trip history; Calendar. Subviews map exactly to v13's identity/readiness/documents/finance; evidence/schedules/reminders/history/mileage; recent checks/templates; open/historical work; location/telemetry/driving/alerts. Lists and Cards share a source, query and actions. Calendar/trip/map specialised views retain their own useful layouts. Search and filters share a compact toolbar; do not reintroduce the trip heading gap.

Server state owns all IDs, timestamps, source versions, permissions, readiness, saved catalogue options, upload states, renewal identity and mutation outcomes. UI state owns selection, open dialogs, steps, filters and explicitly recoverable unsent drafts. Never show a saved result before the server accepts it. Validation redirects focus to the exact step/field, failure retains values and files where possible, cancellation guards dirty drafts, and completed commands refresh source projections.

## Canonical source findings and required work

- **Compliance / RUC / mileage / readiness (I1):** Asset expiry and odometer columns are current legacy projections. Add versioned source records with retained provenance, explicit applicability and assessment; do not backfill approvals from populated dates. Fleet expense mileage is not odometer authority. One server assessment must gate all booking/use/release transitions and their UI projections.
- **Vehicle controller:** existing `show` loads raw work orders/bookings and broad active sites/eligible drivers; replace with scoped DTOs. Existing technology projection must keep its separate permission. Bound or paginate history without pretending the first page is a complete total.
- **Documents:** `AssetDocument` and `AssetDocumentController` are canonical. Existing upload trusts a client MIME, uses original-name paths, lacks retry identity, lineage and scan states; destroy deletes bytes and row. Extend compatible storage with durable private, content-validated/scanned uploads, replacement lineage and archive history. Existing generic asset routes must not bypass new vehicle protections. `Services/Files/MalwareScanner` and the reservation/scan/recheck pattern in `Sites/VendorAgreementFiles` already exist. Unknown scan state cannot become available evidence.
- **Schedules:** `FleetServiceSchedule` supports days/km only. Existing mark-complete overwrites the completion and advances from the due mileage even without an observed completion. Retain completion records with actual source date/mileage and canonical work/evidence references. Calendar months use no-overflow arithmetic; historic days remain days. Scope all schedule reads/mutations to approved assets and current permission. Both shared `FleetMaintenanceProvider` and `FleetServiceScheduleObligationProvider` already project the source.
- **Checks:** `FleetChecklistTemplate/Run`, `MaintenanceCheckService` and policy question snapshots own the workflow. Add controlled library publication/version/retirement and assignment without rewriting submitted questions or granting new operating policy. Existing checkbox/text/number/select support and file endpoints must remain compatible. Failed/submitted sources enter canonical Maintenance via its current report/check path.
- **Reminders:** shared Tasks aggregate provider sources instead of storing a competing Task model. Add a persisted vehicle reminder source and provider, not a shadow task system. Document renewal groups maintain one source identity across versions. Completion affects the reminder only. SiteCalendar must reuse the same source and permission boundary.
- **Bookings/calendar:** `FleetVehicleBooking` and `VehicleBookingController` own booking/custody. Keep explicit approval routes, current HR/site checks, idempotency, conflict locks and observations. Vehicle Calendar projects shared booking/appointment/reminder/restriction records with source privacy; it must not infer availability from gaps or equate estimated work with a confirmed appointment.
- **Maintenance:** `work-orders/show.tsx`, `MaintenanceTransitionService`, `MaintenanceCheckService`, `MaintenanceRestrictionService`, `MaintenanceAttachmentService` already implement canonical work and independent release. Vehicle actions open those sources with return context. No separate maintenance lifecycle, completion-as-release, or Finance posting from repair.
- **Finance:** reuse `AssetFinanceTechnologyProjectionPresenter` and `MaintenanceFinanceService`; do not sum purchase orders and resulting bills as separate spend. Permission-limited readers receive coarse state, not identities/amounts hidden by Finance.
- **Geofences:** reuse AssetGeofence and current Client location workspace interaction. Geometry/assignment/monitoring are distinct. Greyscale fills the map surface; right-click menus are small context menus, marker hover shows timestamped reported state. Keyboard buttons provide the same actions.
- **Telemetry/insights:** canonical Fleet events/state/trips/signals remain sources. Current driving metrics use raw packet counts, hardcoded fallback thresholds and an initial 100 score; the new vehicle view must not portray those as a validated driver score. Require configured/versioned policy, sufficient coverage and verified attribution, expose unavailable/partial data and disputes, and correlate source events with Control Room receipts. Hardware protocol and approved road-limit provider remain activation prerequisites.
- **Trips/exports:** range/filter/pagination are server-owned and share authorization with private exports. Journey events contain actual coordinates and known address provenance, selecting one focuses the map. Export actual PDF/XLSX with brand/Unicode/maps and clear missing coverage, never a CSV renamed XLSX or fabricated route between missing points.

## Compatibility and verification expectations

Each bounded backend contract records its exact migrations, routes, DTOs, lock order, legacy projection/backfill policy and rollback refusal before dependent writes. Migrations are additive and run only under the verified disposable package database profile. No reinterpretation or destructive removal of old records. Record baseline failures separately from package defects. Native picker/Excel and genuine browser zoom require actual verification; headless viewport changes are not substitutes.

The above gaps are initially unimplemented. Close them in the checkpoint/issue ledger only with the corresponding code and evidence.
