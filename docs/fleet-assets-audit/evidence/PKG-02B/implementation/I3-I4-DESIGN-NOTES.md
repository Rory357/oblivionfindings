# Remaining source adapters and frontend plan

Root preparation during I1 backend custody; no implementation or new grant implied. Preserve Main's full scope and resolve these adapters locally in bounded increments.

## Calendar and bookings

Vehicle Calendar uses the approved Month / Week / Day / Agenda / Timeline UI against canonical records. A range endpoint returns source-tagged entries from FleetVehicleBooking, current Maintenance appointments and advisory estimates, persistent reminders, compliance source dates and restriction history. Return actual timezone/range and stable source IDs; never duplicate obligations as editable calendar events. Source permissions determine full details or busy-only projection. A restriction with no end remains active across the displayed range. An empty day is not an availability assertion.

Right-click on an empty date/time offers request booking, plan service, add reminder and view day, plus only actions permitted for that vehicle. Record right-click offers source-specific view/edit/reschedule/cancel/duplicate/reminder/linked evidence or history as appropriate; deletion of source history is not a generic calendar action. The visible More menu and keyboard context-menu key provide the same options. Selection seeds date/time fields without inventing a provider confirmation. Every mutation uses the canonical source command and refreshes the same calendar range.

I1 supplies current readiness gates and explicit approval route. I3 completes source-validated pre/post checks, custody/return, idempotency, actual current observation, actor/driver distinction where already supported, timezone validation, relevant date coverage and concurrent conflict handling. Current approval and checkout must recheck authority rather than trust request-time state. Defaults use the server's current local time; historical edits retain intent and validate separately. Daylight-saving ambiguity/missing local time needs explicit validation. A returned vehicle can still be restricted; return is never a release action.

## Geofence and device mapping

Use AssetGeofence with `asset_geofence_assignments`; never create a second registry or revive GeofenceZone. Retain assignment history and exact geometry revision when linking or changing shape. Shared Client Location behavior is the UI reference: greyscale basemap, right reported-state column with motion icon, compact linked geofences and clear owner, selection/create/manage actions. Geometry editing must not silently enable monitoring, change existing client consent, or claim an alert rule is active. Current canonical site/ownership checks apply to geometry choices, assignments and histories. Changes affecting established consent semantics would be an escalation; reusable vehicle entry alone is authorised.

Actual Device/link/assignment and FleetVehicleStateSnapshot/FleetTelemetryEvent own observations. Report observed_at and received_at, ignition/motion/speed/voltage/power/location/accuracy with units and unknown states. Null must never become zero/off/stationary. Retain canonical model/firmware/protocol/capability provenance; GV500CG model confirmation alone is not proof of ECU VIN, direct diagnostic faults or dashboard odometer extraction. VIN remains the vehicle record until a verified supported observation is explicitly reviewed. No remote engine/device control is introduced.

Map canvas fills its block with accessible controls and compact right column. Marker hover shows reported state and age; right-click on map versus vehicle yields different small menus. Fit route and selected journey event must update the same map. Map imagery failure leaves the recorded coordinates/controls usable and labelled; do not fabricate a live road map. Existing LeafletMap hardcodes external tiles; the new vehicle adapter must respect approved provider configuration and the release's prohibition on unapproved private-coordinate transmission. No new API key, provider spending or geocoder activation. Synthetic browser fixtures are isolated and cannot become live policy.

## Telemetry, Control Room and driving insights

FleetSignalService, FleetSignalOutbox and DispatchFleetSignalOutbox already own reliable publication. Use their signal IDs, idempotency and exact Device/Asset/Site provenance to correlate collision suspicion, supported faults, overspeed and other configured events with the resulting Control Room record and delivery state. Use existing Control Room triage/lifecycle and canonical MaintenanceReportService to create/link work from the exact source. A vehicle page must distinguish pending delivery, delivered, acknowledged/triaged and resolved; it cannot promise that a local packet already created an alert. Closing work, releasing vehicle and closing the alert are independent.

Do not expose raw payloads or unrelated people because a caller may view the vehicle. Use current FleetRealtimeAuthorizationService/SecurityDevices access contracts and privacy flags. Personal and consent-blocked trips must not enter business driver analytics or exports; historical/source projection needs the canonical privacy decision. A revoked current device assignment must not expose newly attributed observations through stale UI or delayed export.

Current FleetDrivingMetricsService counts packets against fallback configuration and starts at 100. Preserve legacy rows as legacy; do not relabel them validated driver scores. New insights require recorded policy version/weights/thresholds, event episodes rather than duplicate packets, valid reported distance/time exposure, coverage and source freshness, and verified driver attribution. Missing attribution stays vehicle-only. Insufficient coverage or unconfigured policy means score unavailable, never perfect driving. Per-trip view explains contributors, overspeed source, coverage and original events; disputes retain original evidence and a reviewed disposition, and any recomputation records its policy/version.

Road limit adapters may support an approved OSM/Google/local source and manual verified overrides, but geometry matching, direction, timestamps/source version and unknown coverage stay explicit. Unknown limit cannot become a default legal road speed. A configured fleet threshold and a road limit are different sources. Deduplicate continuous exceedances and gate Control Room delivery on recorded operational policy. No external lookup of private coordinates during development or live activation without configured authority.

## Trips, private reports and Finance

FleetTrip/segments/events own range/filter pagination. The compact approved trip list and map/details area share selection; journey timeline shows known recorded address or coordinates with provenance, and List/Cards/Table share event actions. Preserve missing-report gaps instead of drawing certainty through them. Searchable driver filter uses current authorised driver choices. The user-requested compact toolbar remains one grid without an orphan top row.

Export requests use the same date range/timezone/driver/event filters and current scope as the displayed data, without silently exporting only its first page. Include requested range, actual count/coverage, source/provenance, per-trip statistics, maps of recorded positions, organisation branding and Unicode text. PDF uses the existing locked Dompdf dependency and an embedded Unicode font. Excel must be an actual XLSX package with embedded images, typed safe cells and sheet pagination, not renamed CSV/HTML. Server creates private artifacts, rechecks access at delivery and logs export reason/scope; direct IDs cannot bypass access. Fonts/logo/images are local approved assets. Map imagery is drawn from approved source data only; no hidden external map fetch. Native picker/Excel rendering and genuine zoom remain actual verification items, not inferred from build success.

Finance reuses AssetFinanceTechnologyProjectionPresenter and MaintenanceFinanceService. Keep fixed asset, purchase, invoice, approval and payment ownership in Finance. Permission-limited users see the approved coarse state. Open existing source/review handoff with vehicle context; never create duplicate amounts or post/approve from a vehicle edit.
