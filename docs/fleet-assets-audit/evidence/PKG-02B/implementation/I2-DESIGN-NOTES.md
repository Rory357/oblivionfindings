# I2 dependency design — documents, catalogues, service and follow-up

Root preparation while Sol owns I1. **Not a writer-custody grant and not implemented.** Split into I2a documents/catalogues, I2b service/reminders and I2c checklist library/handoff. Confirm exact schema and legacy call-site compatibility at each custody handoff. Source mapping below avoids competing ownership.

## I2a — durable documents and reusable choices

Reuse AssetDocument. New private files retain byte hash, server-detected MIME, size, uploaded actor/time, retry key/fingerprint, scan state and immutable version lineage. A file group represents one policy/agreement/certificate with several pages/files and one renewal source. Replacing one page must not create a second renewal task. Keep existing AssetDocument title/category/version/effective_date/expiry_date columns as historical file metadata; group/source metadata owns the current effective/expiry dates. Explicit metadata edits require expected source version and retained before/after history.

Additive candidates: `asset_document_sets` (Asset, kind/title/reference, dates, optional responsible current staff, lock_version, archive provenance); `asset_document_set_events` (immutable actor/action/source-version snapshot); AssetDocument series/revision/set/replaces pointer, state/hash/request identity/archive provenance; Asset.profile_photo_document_id referencing an authorised clean same-Asset image. Legacy documents receive no fabricated clean state; retain their original paths and metadata and make trust explicit. Existing non-vehicle document behavior remains compatible. Vehicle entry points, including old generic AssetDocumentController download/destroy/store routes, must enforce the new private/version/archive rules rather than bypass them.

Permission uses existing AssetPolicy document authority and current canonical vehicle scope. Fleet vehicle management alone must not silently grant Finance/document access. Return can.documents_manage separately. Source-linked evidence must resolve an allowed same-Asset compliance/schedule/check/work source and preserve that owner; a guessed source_type/source_id is not a valid link.

Storage flow: reserve immutable upload identity; validate MIME/content/size and private path; write bytes; scan via existing `Services/Files/MalwareScanner`; recheck current actor/site/version before publication. Old ready version/photo remains current until replacement is clean and committed. Scan unavailable/infected/storage failure produce explicit recoverable states; retries use retained identity and cannot create duplicate available versions. Never claim scanned when only an extension was checked. Clean files download only after current object and permission checks; no raw disk paths or public URLs in DTOs. Archive retains original file/history and requires a reason. Active renewal follows group identity, and archiving evidence does not silently change a compliance outcome.

Persistent searchable Add new choices need stable IDs, normalised duplicate handling, permissions and audit. Reuse canonical AssetCategory, Site, User/HR driver, Vendor and Finance owners where they exist. A bounded Fleet catalogue may own only otherwise missing simple labels such as service type, body type/use purpose, document category, reminder type and explicit interval presets. A new service interval stores numeric quantity/unit; default unit in the form is months, with legacy day intervals retained. Never turn statuses, permission states, compliance outcomes or legal applicability into arbitrary custom labels. Identifiers (VIN, policy reference), descriptions and reasons remain text because searchable options are unsuitable there.

## I2b — source-owned service history and reminders

Extend FleetServiceSchedule compatibly with optional interval_months, explicit source/reference, owner and version. Existing interval_days rows remain day-based. A row cannot ambiguously own both days and months. Completeness does not imply approved interval policy; the operator records the actual source. Calendar-month next due uses no-overflow arithmetic from actual completion, including leap years and month ends. Kilometer due uses actual completion observation, never silently substitutes the previous due milestone.

Retain immutable service completion history (schedule/Asset, actual date, actual dashboard observation ID/value if supplied, canonical work/report/evidence references, actor, request key, reason and schedule version). Completing a service updates only the next service projection; it does not close/release Maintenance, approve Finance or mark compliance passed. Existing store/update/markComplete endpoints must use the same scoped service and current Asset lock. Old summary/task/calendar views read those same updated source fields.

Shared Tasks is a provider-based feed, not a canonical standalone Task table. Add FleetVehicleReminder as an owned source with explicit Asset, kind/title, related source identity/version, due date/time/timezone, owner, delivery policy, state, expected version and immutable event history. Register a site-scoped Tasks provider and SiteCalendar obligation provider. Manual reminders, grouped document renewal and schedule follow-ups use the same lifecycle; task identity remains stable through source replacement/reschedule and history stays visible. Completing/snoozing a reminder never completes its obligation. Cancellation and repeated requests are idempotent. Missing or withdrawn owner authority is shown as owner unavailable and does not leak their hidden profile.

Notifications, if configured, use durable deduplicated outbox/effect records and current recipient access checks. No real external delivery in this build verification. Do not invent an escalation interval, default recipient or approved operating policy. A follow-up may exist in the shared in-app feed with no external delivery enabled.

## I2c — controlled checklist library and canonical handoff

FleetChecklistTemplate and immutable FleetChecklistRun snapshots remain owners. Published template versions are retained; customising produces a new draft/version, never edits an old submitted template. Ordered questions support existing typed values/options, requirements and evidence rules. Publication and operating assessment policy remain separate: creating/publishing a library template does not fabricate an approved MaintenancePolicyService rule or automatically make a submitted run passed. Explicit assignment records can point to published versions while runs retain the exact displayed version.

MaintenanceCheckService currently strips client evidence_verified, writes private files and captures original answers/template/rule. Extend its evidence scanning boundary consistently with I2a without falsifying old trust. Normalise typed input against the submitted version, reject foreign attachment IDs, preserve failed/needs-assessment original outcomes and correction lineage. Existing inspection entry accepts metadata odometer but does not create a retained odometer observation; integrate with I1 source recording under the Asset lock and retain provenance.

Failed/needs-assessment handoff opens or links canonical MaintenanceReportService using the original run source. Preserve approved Coordinator/backup routing, current site staff and duplicate/retry semantics. If automatic handoff is requested/configured and routing is unavailable, retain the original submitted check with an explicit durable pending/failed handoff record; do not fake successful work creation or discard the observation. A retry must link one source to one original report/work action. Evidence, original outcome, retest, independent release and custody remain distinct.

## Verification to carry into bounded contracts

Private file foreign-ID denial; spoofed MIME/oversize/empty input; clean/infected/unavailable scan; interrupted storage/publication; replacement race and retry conflict; current permission withdrawal; archive/download history; same renewal ID after multi-file replacement and date edit; months/day compatibility including 31 January/leap dates; supplied actual mileage and no invented completed reading; reminder completion leaving obligation unchanged; owner loss and no external sends; immutable template versions and failed-run handoff/retry; typed required evidence; old route bypass regressions; additive migration/backfill and guarded rollback refusal with real new evidence.
