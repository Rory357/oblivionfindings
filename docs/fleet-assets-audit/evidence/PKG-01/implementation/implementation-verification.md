## Implemented source boundary

- One operating organisation. Every read and write uses approved site, capability, canonical asset/work identity and direct-object denial. There is no tenant selector or new tenant scope.
- Each report is a separate retained source with idempotent submission, approved site Coordinator/backup route, optional observed time, optional estimate and private evidence. A related report can point to an existing canonical work order without overwriting either report.
- Exact approved site/category rule snapshots govern checks and retests. Unknown or old provenance stays Needs assessment. An explicit approved `availability_impact=advisory` may make a failed/unassessed check advisory for booking; explicit active restrictions always block.
- Work commands share the canonical asset lock, current actor/site recheck, work version and idempotency key. Progress, next action, handover, provider plan/response/cancellation/completion, repair attestation, custody and release append attributable actions. Provider plan is not confirmation. Work completion, estimated date and Finance state cannot clear a hold.
- Independent release requires the current category/site reviewer grant, approved repair/retest/release rules, a separate repair attestor, saved service evidence, a fresh passing retest covering the exact active restriction set, newer-check review and custody receipt when required. Booking and release use current locking reads after the asset lock so an overlapping transaction cannot rely on a stale MySQL snapshot.
- Release effects are persisted with retry and idempotent delivery through `maintenance:dispatch-effects`. The after-commit trigger and one-minute scheduled retry are both wired behind `FLEET_MAINTENANCE_EFFECTS_ENABLED`, which defaults to false in staged environments. Enabling operational delivery belongs to activation review.
- All Tasks projects the canonical work ID only when a target exists within the seven-day horizon. Completed/cancelled work is filtered by default. The contextual link uses the canonical reference and explains when the work is outside this scope. Vehicle and generic asset profiles, work queue, and Site Calendar read the same source. Site Calendar labels report windows as all-day estimates and internal provider windows by their latest planned, confirmed, cancelled or completed state. Finance bill links only expose a current matching canonical bill under Finance read permission; stale allocation/deletion shows reconciliation required, and maintenance never approves/posts a bill.
- The desktop UI uses the approved five-step problem report, shared calendar and time pickers, compact work summary/progress, source history, provider workflow, private evidence, release review and scoped Finance search/link. Auckland wall minutes are converted by the server; DST gaps are rejected and repeated minutes require the chosen offset.
