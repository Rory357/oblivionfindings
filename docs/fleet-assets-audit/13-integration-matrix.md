## Contracts to resolve before dependent implementation

1. Canonical resource/Site/Client ownership and direct-object denial for every sibling endpoint, including nested records and embedded Site views.
2. One availability/readiness contract and resource restriction lifecycle with approved policy, separate from calendar rendering.
3. Immutable inspection/template/evidence and release authority, with legacy evidence explicitly labelled.
4. Client request allocation link and minimally disclosed booking purpose/driver/Client context.
5. Independent personal-location collection/viewing/sharing and employee trip privacy, with policy validation for retention/emergency handling.
6. Finance-owned approval and source-event identity across single/bulk transitions, reversal/correction and replay.
7. Canonical geometry version/rule semantics and consent-safe outbox/response delivery.
8. Source-owned failure/partial/unavailable state, named recovery owner and realistic scale acceptance.

These are proposed contract work, not permission to change upstream HR, Finance, Clients, Sites, Control Room or Rory's design-rule documents without the appropriate bounded package approvals.
