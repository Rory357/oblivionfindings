# HR and Site Canonical Access Remediation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove legacy organisation partitioning from active HR and Site access while preserving storage compatibility and replacing every former partition check with canonical Site, current-employment, ownership, audience, privacy, sensitivity, or explicit application-level permission evidence.

**Architecture:** Oblivion Findings is one application for one operating organisation across many Sites. `UserSiteAccessService` becomes Site-only, reusable HR access services own current-staff and audience decisions, domain policies remain responsible for ownership and sensitive records, and `LegacyStorageContext` may write required compatibility columns but may never filter, select, compare, or authorize active records.

**Tech Stack:** PHP 8.4, Laravel 13, MySQL, Pest 4, Inertia 2, React 19, TypeScript, Playwright desktop web
