# Native build and do-not-copy register

## Binding boundary

Every external project is **benchmark-only**, regardless of licence. This audit authorizes observation of behavior followed by neutral requirements and an original Oblivion implementation. It does **not** authorize importing, adapting or copying source code, UI assets, text, schema, API shape, icons or distinctive screen composition. No compatibility or licence-reuse assessment was performed. Any future reuse or integration requires a new, explicitly authorized legal/security/architecture review.

All 97/97 prompt-listed repositories now have project-specific behavior, immutable primary-source loci, a licence/edition boundary and an explicit Native, Reject or Separate future decision, plus one separately labelled supplemental upstream, `frappe/frappe`; the prompt denominator remains 97. The catalogue gate is therefore **97/97 (100%)**, but catalogue relations do not automatically grant target completion credit. Target-specific research also pins official upstreams outside that initial catalogue where required. Against the canonical 904-target register, **411 targets have a verified benchmark mapping, 89 have a target-specific documented No Credible Match decision, and 404 remain completion-unproved**: 500/904 (55.31%) currently have evidence-preserving dispositions. An unproved row is not evidence that no relevant project exists globally.

## Important exclusions and maturity/edition caveats

- Timefold Score Analysis is Enterprise-only and was excluded; only community hard/soft/pinning semantics are used.
- CISO Assistant top-level `enterprise/` is commercial and excluded; only cited community paths are used.
- OpenProject is open-core; only cited community behavior is used.
- BeaconHS is very young/low-adoption and is a low-maturity behavior reference, never assurance.
- Odoo Community asset/consolidation claims were not used; module/edition licensing varies.
- libOSDP is a protocol behavior reference, not a complete physical access product.
- Grocy/Mealie/Tandoor are household/recipe references and cannot establish clinical IDDSI/allergy authority.
- ERP products cannot establish NZ GST payments-basis, IRD, supported-living funding or client-money compliance.
- Identity/IoT project concepts must not introduce multi-tenant framing into Oblivion's single-tenant multi-site architecture.
- OpenSlides keeps the canonical root SHA separate from the official backend SHA used for the cited behavior; neither identity may substitute for the other.
- In the superseded 740-row projection, at least 87/229 selected rows overextended the cited behavior beyond its source anchor. That historical warning drove the stricter final-ID mapping rules; it is not a current denominator. The current completion gate is 500/904 (55.31%) mapped or documented No Credible Match and 404/904 unproved.

## Native design rule

For every finding: preserve the verified user need and safety invariant, translate it into actor/site/state/provenance/error/recovery requirements, then implement in Oblivion's Laravel/Inertia/React architecture and terminology. Use existing PageHero, WizardShell, Dialog/Sheet and domain services where they fit; never reproduce an external product's layout or wording.
