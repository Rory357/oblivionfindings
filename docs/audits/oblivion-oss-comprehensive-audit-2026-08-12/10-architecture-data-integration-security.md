# Architecture, data, integration and security

## Security model

Oblivion is **single tenant with multiple sites**. Every recommendation uses site assignment, role/permission, ownership, parent-child relationship, direct-object denial, minimum-necessary field disclosure and explicit global-role exceptions. “Tenant” controls are not proposed.

Runtime permission middleware covers 2,608/3,024 routes with 393 unique permission atoms and 429 OR expressions; 21 routes use `role_scope:my-day`; there is no direct `role:` route middleware. Middleware presence is not object authorization. The most widespread P0/P1 roots are the gap between broad permission and row/relationship scope.

## P0 architecture roots

1. `ARCH-P0-A`: Control Room child resources do not bind to the authorized alert/site.
2. `ARCH-P0-B`: device identity, telemetry, location and custody are permission-global rather than derived from authoritative temporal custody.
3. `ARCH-P0-C`: safety delivery is durable only after an outbox exists; source-before-outbox and caught routing/observer failures lack automated replay.

These roots intentionally de-duplicate task/evidence/discussion/escalation variants, device/tracking/assignment variants and domain routing catches without losing anchors in `findings.json`.

## Canonical ownership assessment

- Client/person identity and site relationships must scope care, clinical, eMAR, respite, HR and portal projections. Portal controllers sampled in Pass 8 correctly bind client/user; a blanket portal IDOR allegation was rejected.
- Security & Devices should own canonical device identity, provider-observed state and integration health. Sites/Assets/Fleet/Control Room link temporal place/custody/context. Current generic local updates and provider sync compete for the same fields (`SEC-PROV-003`).
- Asset owns operational lifecycle/custody; Fleet owns vehicle operations; Finance owns depreciation/GL. `ASSET-RBAC-01` shows policy/controller divergence; finance acquisition/depreciation requires source and occurrence lineage.
- Control Room owns alert lifecycle. Domains emit governed signals; direct terminal updates from incident/safeguarding and pre-outbox gaps violate the boundary.
- Governance should consume access-filtered operational/financial projections. Cross-parent agenda/budget mutations (`GOV-NESTED-01`) and advisory spend/budget gates require owner review, not a second operational source.
- Audit/timeline must be access-filtered projections with immutable provenance. Sensitive before/after snapshots and fail-open audit writes remain P1 architecture concerns even where not a separate roadmap root.

## Data and relationship risks

The dominant pattern is independently validating IDs that must form one aggregate: medication-round-resident, clinical schedule-protocol-resident/type, respite stay-resident-incident/plan, funding agreement-client-line-delivery, transport resident-shift-asset-medication and nested safeguarding/governance records. Acceptance must exercise every mixed-ID permutation and assert denial before disclosure or side effect.

The second pattern is ambiguous or duplicated ownership: empty site scope as both global and none; local/provider device fields; client/care clinical legacy chart stores; SiteVendor versus finance vendor; operational amounts versus GL source documents. Consolidate ownership before UI consolidation.

## Async and integration boundary

- 96 queued jobs, 14 events, 10 listeners, four explicit outbox model/dispatcher artefacts and 29 observers were classified.
- Outbox retry after row creation is a current strength. Transactional creation/reconciliation, stable source identity, dead-letter/operator replay and null-site disposition are incomplete.
- Webhook requests require the decrypted integration key; the earlier “unauthenticated” hypothesis was rejected. The retained issue is configured site/device binding and deterministic replay identity; optional HMAC is defense-in-depth unless the provider contract mandates it.
- UniFi sends a decrypted credential with TLS verification disabled (`SEC-UNIFI-TLS-01`) and advertises health whose production pull is TODO/empty (`SEC-HEALTH-004`).
- Signal processing has an application-level race that can create duplicate active alerts (`CTRL-SIGNAL-002`).

## Finance/data integrity boundary

Finance contains substantial posting/transaction behavior and is not a placeholder. Retained roots are evidence-specific: GST metadata/basis, exactly-once reversal and recurring occurrence, bank-reconciliation relationship/terminal state, payment-match concurrency/reversal, consolidation quarantine, settlement evidence, client/donor funds and delivery-claim provenance. The adversarial pass rejected a blanket “payment run is non-atomic” claim because transactions and meaningful checks exist.

The Financial Insights JSON family adds a separate P1 authorization evidence gap. All eight routes use the broad `finance.dashboard` permission. The single-client and single-site actions then accept caller-controlled integer IDs, and the inspected controller/service path contains no policy, site-access or caller-to-record guard before loading client/site financial data; client summary also uses `Client::withTrashed()`. This proves a missing target-level guard and denial-test gap, not a deployed exploit or a decision that every finance role must be site-limited. The finance/security owners must explicitly classify each endpoint as global, organisation, site or client-relationship scoped, represent any global exception deliberately, decide deleted-client visibility and prove wrong-site/wrong-client denial. Exact static evidence and limitations are in `evidence/source/finance-insights-direct-object-review.json`.

## Operability and evidence limits

Static review found no basis to claim production performance, backups, restore time, queue latency, query plans or external-provider behavior. Tests were inventoried but not run; no load, failure injection, queue replay, restoration, security scan or penetration test occurred. Acceptance plans therefore require metrics, structured failure state, correlation/source IDs, reconciliation jobs and operator-visible recovery rather than assuming logs are enough.
