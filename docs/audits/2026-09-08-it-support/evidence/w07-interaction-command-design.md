## Speaker and responsibility proposal requiring source review

- Capture who spoke at commit time. Participant precedence: requester or requested-for participant is requester-side even if the same user can also work this ticket. Otherwise current `canWork` is IT-side. The existing policy allows some visible non-working staff to comment publicly; retain that capability but record them explicitly as an observer rather than treating a global permission as an IT response. An observer can be shown as latest public author without silently claiming the responsible IT team replied.
- Persist the actual latest public comment/reference/time and its captured side. Keep a separately explainable next-response party: requester-side public reply asks IT for the next response; IT-side public reply asks the requester; an internal note, delivery receipt or watcher change does not move it. A public observer comment preserves the preceding responsible-party evidence. Creation starts with IT responsibility. This is conversation responsibility, distinct from explicit waiting vendor/approver/team or SLA pause policy; do not overwrite those operational fields.
- Use deterministic comment order `(created_at,id)` and the ticket lock, not timestamp alone. Stamp first response only for the first public IT-side interaction. Resolution/public reopen writers must use the same provenance/response helper while retaining their separate governed transitions (full W09 changes later).
- Add a genuine Awaiting IT projection/filter/count/hotlist from the same canonical responsibility predicate. Preserve the existing first-response metric and compatibility links. The final choice between keeping `awaiting_reply` as the compatibility key or adding `awaiting_it` must be consistent across URL parsing, saved filters, hub summary and drilldowns; no mix of old first-response counts with new queue rows. Include all currently open statuses when conversation responsibility calls for IT even if a vendor dependency still governs workflow.
- Historical backfill must be bounded, restartable and previewed. Current user permissions cannot establish an old author's role, and requester identity may have changed. Preserve existing comments and SLA timestamps; mark insufficient historical speaker/responsibility evidence unknown. Do not fabricate an IT response or silently move ambiguous old work into a measured queue. A new verified public interaction can establish responsibility going forward.
