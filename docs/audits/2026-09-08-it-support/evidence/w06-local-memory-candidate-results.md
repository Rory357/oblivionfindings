# W06 document-memory recovery authorization

Implemented source on 9 September 2026; final test result and real-browser verification are recorded separately below. This does not enable persisted drafts or choose retention.

The shared canonical draft controller/service now provides `POST /it/drafts/validate-local-candidate`. It is a permission check for an existing browser-document memory buffer, so it remains available while `it.drafts.enabled=false` and does not read or create an ItTicketDraft row. Current actor approval, IT capabilities, canonical ticket audience and selected reference scope are rechecked before issuing a proof.

The request binds original `actor_user_id`, purpose, exactly one ticket_id/request_uuid context, opaque local `memory_uuid`, fresh snapshot-bound `candidate_uuid`, partial allowlisted fields, step_index and original base_ticket_version. Optional bound_scopes retains up to100 prior canonical selection snapshots as a resource bound; every previous scope and the current fields are independently authorized, including a Site that was subsequently replaced or cleared. Scope entries permit only canonical Site/organisation-wide, staff, watcher, service, asset/device, provisioning and queue references.

The response contains only candidate identity, original/current ticket versions, authorization, submit capability and a safe blocker. It contains no private field values, files, draft row metadata, saved timestamp or invented expiry. A changed or settled ticket can authorize review while leaving submission blocked; the original version is never silently replaced. An already committed intake requires the existing canonical receipt recovery, and that link is concealed if current record access is unavailable. A proof is not a commit capability; canonical mutations still authorize and validate normally.

The existing protected IT draft response middleware forces JSON, prevents old-input flashing, supplies no-store/private headers and suppresses private debug/error text. Client integration must keep original Files only in document memory, hold exact actor/purpose/context/generation boundaries, bind each proof to the frozen snapshot and consume it once. Metadata-only discovery precedes explicit Resume/Discard. Native Back recovery is not accepted until these client and browser checks pass.
