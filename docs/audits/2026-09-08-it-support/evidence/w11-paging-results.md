# W11 discovery and acknowledgement recovery

11 September 2026. Paging and ACK recovery implemented with focused regression evidence below. Whole W11, F05/B02/E10 and the Goal remain incomplete.

## Scope

The canonical poller now stages provider identities in `ItInboundEmail` before changing unread flags. A captured cutoff and encrypted continuation are persisted on `ItMailboxConnection`. Discovery is bounded to five pages per job; processing is bounded to 100 records. Remaining work resumes through the existing hourly/manual poll, without adding a second schedule or dispatching recursive sync jobs. A partial batch does not stamp `last_polled_at`.

Each transport identity includes the provider, connected account, effective mailbox and case-sensitive remote ID, hashed into a unique key. Remote IDs and cursors are encrypted and hidden from model serialization. Staging retains no message body. Ingestion updates the discovered canonical row within the existing poll claim transaction. Processing attempts, acknowledgement attempts, safe failure codes, retry time and acknowledged time survive subsequent jobs. Missing RFC Message-ID quarantine therefore has an ACK-only recovery path. Existing RFC Message-ID duplicate results can be linked by a separate transport receipt without making another ticket.

Provider-wide authentication/permission/configuration/rate-limit failures stop further provider work. Other message failures retain their own receipt and allow independent messages to proceed. After a completed discovery chain, a failure or bounded yield starts a fresh scan next time, preventing a permanently failing older message from pinning newly arrived mail. Invalid/rejected continuations restart discovery against the existing unique receipts. Interrupted incomplete scans retain their next page. Account/mailbox changes cannot process a previous account's scoped receipts.

Graph continuation URLs are checked before authenticated HTTP: exact HTTPS Graph host, effective mailbox and inbox message path, no user info, port, fragment or control characters. The full opaque query is then used unchanged. New discovery/detail/ACK requests use immutable IDs. References: [Microsoft paging](https://learn.microsoft.com/en-us/graph/paging), [Outlook immutable IDs](https://learn.microsoft.com/en-us/graph/outlook-immutable-id), [Gmail message listing](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/list).
