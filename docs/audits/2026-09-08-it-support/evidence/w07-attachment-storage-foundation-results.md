## Source and contract

- [Migration000010](../../../../database/migrations/2026_09_09_000010_create_it_attachment_storage_intents.php), frozen SHA256 `0f5d3487ab98361b9f9fafa90a4b0017666f6a636f0eb4e2bff823aba5443f31`, adds only technical storage intentions. There are no actor/parent foreign keys because those canonical rows may be locked and uncommitted when reservation metadata must commit independently. Populated evidence prevents rollback of this table.
- [ItAttachmentStorageIntent](../../../../app/Models/ItAttachmentStorageIntent.php) and [reservation reference](../../../../app/Domain/It/Data/ItAttachmentStorageReservation.php) preserve immutable UUID/path, actor/parent, content/name fingerprints and size. Terminal tombstones cannot be deleted/reused; an attached reference cannot be reassigned. No raw file name, content, credentials or provider response is stored on the intention. `ItAttachment` remains the sole canonical attachment record.
- [ItAttachmentStorageIntentService](../../../../app/Domain/It/Services/ItAttachmentStorageIntentService.php) implements `reserveDirect(parent, files, actor)`, `storeReservedDirect(parent, files, actor, references, storedPaths)`, `requestRollbackCleanup(references)` and bounded `retryPending(limit)`. [ItAttachmentStorageService](../../../../app/Domain/It/Services/ItAttachmentStorageService.php) exposes these as four delegates; its existing direct/draft methods retain their prior behavior.
- The approved, optional final `systemActor = false` parameter on [AuditLogger::logOrFail](../../../../app/Services/AuditLogger.php) keeps every existing caller's attribution and privacy behavior. Mechanical cleanup uses `systemActor: true`, retaining `original_actor_user_id` as provenance. The audit table's nullable `users` foreign key would otherwise reject a removed uploader or stale authenticated actor. The ordinary `log()` signature is unchanged.

All file validation/fingerprinting precedes physical writes. Reservations commit through an independent connection derived from the current primary configuration. After canonical business authorization/replay checks, the caller holds its business locks and acquires intention locks by ascending ID before the first copy. Each canonical attachment and its attached intention state commit together. This service does not replace ticket/audience authorization.

Only a caller's proven rollback may request cleanup. An exception, missing receipt, abandoned reservation or age is not deletion proof. A still-open outer transaction produces a truthful `deferred` count, avoiding InnoDB savepoint-lock self-deadlock. Unknown reservations remain for reconciliation. Cleanup returns counts (`requested`, `deleted`, `failed`, `deferred`, `reconciliation_required`) without replacing the original business exception.

Cleanup fences the same immutable row before checking canonical ownership or touching storage. Failed/throwing deletion remains pending. A physical deletion followed by failed required audit does not complete the DB intention; a later absence check can safely finish it. Attempt evidence is preserved separately if the completion transaction rolls back. Bounded retry prioritizes unattempted/oldest attempts and attempt counts, preventing older persistent failures from starving newer work. Empty cleanup returns zero without accessing a PDO. No cleanup depends on the draft activation flag.
