## Read-only findings requiring coordination

1. **Confirmed source gap: page refresh can retain a previous actor's composer.** `use-ticket-page-refresh.ts` requests `viewer_user_id` but omits the ordinary shared `auth` prop. `tickets/show.tsx` derives its actor and Thread key from `auth.user.id`. `HandleInertiaRequests.php` does not mark `auth` as an always prop. Installed Inertia applies and merges a partial page before calling `onSuccess` (`@inertiajs/core/dist/index.esm.js`, response processing). Consequently a changed-session response can supply another authorized viewer's ticket props while the old actor key and entered text remain mounted. The later acknowledgement mismatch currently shows an error only. Fresh actor projection and immediate concealment/remount on identity mismatch must be verified; a success-callback check alone cannot prevent this state.
2. **Confirmed source gap: commit-triggered refresh is dropped while an earlier read is pending.** The same callback handles delivery Refresh, watcher completion and reply completion. Its pending guard returns without retaining a follow-up request. An earlier GET can therefore settle after a new comment commits, omit that comment and leave no failed-refresh warning. A coalesced follow-up or equivalent ordered refresh is needed. Regression: hold read A, commit B, finish A, confirm a later authorized read includes B exactly once.
3. **Confirmed source gap: the drawer delivery read is unbounded.** `use-it-ticket-peek.ts` aborts on replacement/scope cleanup and rejects late results, but supplies neither a timeout nor a visible cancel-wait control. A hung GET leaves `loading` true and delivery Refresh disabled. Preserve the last authorized conversation and draft while ending a bounded wait with an actionable retry state.
4. **Confirmed source gap: page HTTP access/session failures have no explicit concealment transition.** The Inertia reload hook only handles validation errors, cancellation and completion. Its generic failure does not distinguish a confirmed 401/403/419 non-Inertia response from a network failure. Existing entered work must be concealed after confirmed loss of authorization; ordinary transport failure may retain it visibly. Drawer JSON handling already makes this distinction.

These findings were sent to root before any further implementation. They are not claimed fixed by this document. Browser behavior for each still requires verification after the coordinated fix/build.

## Delivery projection review

`ItTicketCommentDeliveryPresenter` reloads the actor and canonical ticket, checks approval and `canView`, selects only actual public comments belonging to that ticket, and limits non-workers to their own submissions. It exposes status counts, tracking provenance, check time and a narrowly scoped review URL. It does not return recipient names/email, subjects, provider identifiers or diagnostics in the conversation. Internal notes have no delivery projection. Thread repeats the public/worker-or-author rendering restriction.

Current leaf attempts are counted, so a retry does not double-count its predecessor. A historical untracked comment stays unrecorded; a receipted public reply with no recipients is distinguished from missing historical evidence. Accepted is labelled provider acceptance rather than delivery. The Setup review link requires current worker scope, resolves a real public comment, applies the canonical delivery visibility query, and filters before pagination. A moved comment may retain aggregate attempt evidence while its historical ticket scope prevents access to the detailed log; the presenter deliberately omits that link when it cannot establish current log visibility. No additional confirmed presenter disclosure was found in this review. Existing PHP tests were inspected, not rerun.

## Browser prerequisites and evidence format

- Record the correct checkout, isolated browser database identity, reviewed migration set, notification isolation, Build8 manifest/app asset and desktop viewport. Use the existing approved synthetic actors/records; do not infer an actor's scope from their label. Do not change production draft retention or provider configuration.

## Watcher journeys

1. **Eligible add and persisted reload.** A worker opens People & feedback, selects an eligible person and reviews Add. Cancel makes no change; explicit confirmation sends the original actor/version/desired state. Confirm one new membership, one version advance and one correctly named activity event. Refresh the full page and open the drawer: both show the same person. Repeating an already satisfied desired state is a truthful no-op with no duplicate event.
2. **Removal and eligibility changes.** Remove that person and verify persistence/event copy. With an existing watcher whose eligibility was revoked through the approved fixture, confirm the paused-update label and available Remove action; that person must not be offered as an eligible new addition. Verify queued watcher-only notifications stop without claiming that an already accepted message was unsent or that independent requester/assignee audiences were removed.
3. **Self action and restricted roles.** Header Watch/Stop watching uses the same explicit confirmation and versioned operation. A requester or participant-only technician without per-record `can.manageWatchers` sees no management/self-subscription controls or private `receives_updates` field. Settled tickets retain the authorized subscription controls; merged tickets do not. Direct unauthorized requests must remain denied.
4. **Concurrent and uncertain changes.** Two original editors make opposing changes. Stale rejection retains the proposal; Review is read-only and Use reviewed version performs no write. An unknown original request plus same-version opposite membership must not be abandoned by adoption or Close. Close/reopen or same-document navigation preserves that pending intent; exact Retry settles it. Fresh equal-version props after a no-op must show other concurrently added watchers, not just the single locally acknowledged membership.
5. **Keyboard and access loss.** Tab to the selector, choose with the keyboard, activate Add, navigate the confirmation, cancel with Escape and check focus return. Errors focus their message and retain the intended person. Cancel wait never announces server cancellation. Changed actor/current permission denial conceals details and blocks further action; a failed network read offers retry without fabricated success.

## Pristine and successive reply journeys

6. **Pristine creation state.** On a ticket/audience with no saved or local work, wait for its real metadata check. The composer is ready without a false unsaved warning, Resume demand or destructive Start new step. Entering text then clearing it after a saved snapshot still requires truthful saving of the cleared state. Existing nonempty drafts remain metadata-only until explicit Resume.
7. **First and next public message.** Submit one public reply with the original actor/version/UUID. Confirm one comment/receipt and its actual notification intent, independently of dispatch. Only a matching consumed draft clears that work. In the enabled isolated environment, Write another reply checks the exact consumed generation and starts a new one on explicit action; it focuses an empty field without reposting the first message. Submit distinct text and prove two distinct comments/receipts. A failed or mismatched next-generation check keeps recovery available and must not rotate somebody else's active draft.
8. **Audience separation.** Repeat the successive-message check for Internal note. Keep a different public draft while changing audience: no text/files migrate, internal notes produce no public email or Awaiting IT movement, and requester views never receive the note. A later requester public reply returns the current open ticket to Awaiting IT while the legacy Awaiting first reply view retains its old meaning.

## Delivery refresh and log journeys

9. **Current, honest delivery evidence.** Use only isolated canonical outbox fixtures to exercise queued, accepted, delivered, failed/bounced and an explicit retry chain. The same saved public comment changes its displayed counts after Refresh; accepted never becomes a delivered claim, and the predecessor is not counted with its current retry. An internal note has no delivery block; a participant sees evidence only for their own public message. No provider diagnostic or recipient address leaks into the conversation DOM.
10. **Draft-preserving refresh and recovery.** Keep distinctive unsent text and selected files in show and drawer. Refresh, wait, fail and retry the read: entered work remains exact and no comment is posted. Verify the bounded pending state, timeout/cancel, error and retry. Include the read-A/commit-B race from finding 2 and late callbacks after closing/reopening or switching actor. A confirmed session/access loss conceals work; a different actor never sees the previous actor's draft during partial reload.
11. **Scoped log navigation.** Review delivery log opens Setup Operations filtered to that exact public comment, with honest total/page/shown counts. Pagination preserves the comment filter, including a reply older than the unfiltered latest-100 window. Cancel leaving with unsaved work preserves it; deliberate navigation follows the established recovery policy. A requester, hidden comment ID or internal note ID cannot retrieve the detailed log. Verify both native link keyboard navigation and browser Back. Do not trigger a real delivery retry; any retry execution requires the existing proven isolated notification boundary.

The checklist does not close the attachment scanner/quarantine/storage-intent work, full merge lifecycle, provider integration, W08 or the final release gate. Those remain separate current dependencies.
