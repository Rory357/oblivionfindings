Counts and allowlisted batch details require **both existing `it.manage` and `audit.viewAny`**. Missing, unavailable or withheld evidence stays null. Original file names, paths, intent IDs, recipient data and arbitrary exception/result strings are omitted. Cleanup failures use fixed safe copy.
- [Setup controller](../../../../app/Http/Controllers/It/ItServiceManagementSetupController.php) adds the health projection to `operationsAudit.attachment_cleanup` and allowlisted batch details to `automationRuns[].cleanup`, within the existing authorized Operations boundary.
- [Operations component](../../../../resources/js/components/it/it-service-operations.tsx) renders canonical freshness instead of treating any historical success as healthy. It separates live counts from the latest shown batch, uses approved status badges/date utilities, and conceals cached counts after current actor or permission changes. There is no new retry transport or dead control.
- [Recovery runbook](../../../runbooks/it-attachment-storage-recovery.md) records the bounded command, stop/retry evidence, finite-mutex limitation, missing-schema behavior, and exact reconciliation/restore boundaries.
