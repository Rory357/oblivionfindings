# W11 mailbox attachment ingestion

11 September2026. Canonical two-provider file ingestion implemented and verified in isolated backend tests. Full W11, E05/E10 and the goal remain incomplete. Previous goal turn made concrete staging/test progress; this turn connected those records to actual canonical intake and reply commands.

## Implemented

`ItMailboxInbox` now requests attachment-aware message reads from the existing Gmail and Microsoft services. Typed descriptors use private staging before ingestion. No-file messages bypass durable preparation when there is no earlier manifest; an earlier manifest cannot be silently discarded on a later read. Provider HTTP remains outside database transactions. File validation/header failures quarantine on the existing inbound receipt; scanner/storage outages remain retryable and do not acknowledge the message or mark the mailbox healthy.

New `ItScannedEmailAttachment` extends the canonical UploadedFile input with a staged-file reference and hash. It rechecks the current pending receipt, clean scan, filename/path, size and bytes under the final transaction. `InboundEmailIngestor` accepts these files through a separate trusted argument, requires the owned receipt and active `ItAttachmentWriteContext`, and adds file fingerprints to message identity only when nonempty. Existing no-file identity hashes remain compatible. Current sender/site/ticket permissions still run through the existing canonical services.

Creation and replies use existing `ItTicketIntakeService::createCommand` and `ItTicketInteractionService::addCommentCommand`. Existing storage intents recheck scan evidence, copy to the final private file, verify the copied hash and retain clean-scan/source provenance on the final canonical attachment. The additive self-reference is in unapplied migration000019; it prevents removal of scan provenance referenced by a final file. No new ticket, attachment storage system, tenant boundary or permission was introduced.

After accepted ingestion, temporary-copy cleanup is requested inside the same final receipt transaction. Per-receipt cleanup runs after commit and before provider acknowledgement. A cleanup/ACK retry does not read or ingest the message again. Final ledger failure rolls back canonical ticket/comment/files, and the existing outer attachment owner cleans proven rollback copies while retaining the staged original for retry. Quarantined files remain private and excluded from accepted-copy cleanup.

Changed source: `ItMailboxInbox`, `ItMailboxPollState`, `InboundEmailIngestor`, `ItInboundAttachmentStaging`, `ItInboundAttachmentUnavailable`, `ItAttachmentStorageIntentService`, `ItAttachment`, migration000019 and the new scanned-upload class. Added `tests/Concurrency/It/ItMailboxAttachmentIngestionTest.php`; updated existing poll/paging/header fakes for Graph attachment manifests and the applicable provider response-size ceiling. The explicit standalone target is documented in `tests/Concurrency/It/README.md`.
