# W01 separate knowledge and credential audit capabilities

Updated 9 September 2026. Implemented; focused automated verification passed. New-role desktop browser verification and the reviewed local permission migration are still required. W01 as a whole is not marked Verified by this slice.

## Exact capability contract

- `it.knowledge.author`: create and edit drafts, submit for review, return/restore to draft and reasoned draft deletion. Published/in-review content cannot be replaced by the draft edit endpoint. Existing restore returns to draft and clears publication metadata; it never silently publishes.
- `it.knowledge.review`: publish an article already in review and retire a publication with a reason. It does not grant content editing, creation, deletion or restore. No new self-review prohibition is inferred; W21 owns its revision and review workflow criteria.
- `credentials.audit`: inspect canonical global/per-credential audit records within current Site policy. It gives no reveal, copy intent, TOTP, update, rotate or other credential management capability. Metadata remains `credentials.view`; direct Site routes retain `sites.viewAny` and canonical Site policy.
- Author/review capabilities are independent of `it.manage`; audit is independent of `credentials.reveal`. Admin alone receives the new grants by default in `RbacSeeder` and additive/idempotent migration `2026_09_09_000006`. Existing non-admin operational actors are not automatically upgraded. An operational owner must explicitly assign any further grant through normal RBAC.

The deliberate compatibility effect is that a non-admin IT manager needs the author/review grants for knowledge writes, and a revealer needs the audit grant for history. Existing allowed Site/audience exceptions remain unchanged. Partial audience overlap grants reading, while authoring/review requires every stored specific-Site audience (or existing explicit `it.organisationWide` governance authority). Author ownership does not bypass Site access.

## Canonical implementation

- `ItKbAccessService` owns scoped read and per-record author/review capability projections and eligible canonical knowledge owners. `ItKbLifecycleService` locks the canonical article, checks the action grant, guards the stored audience before edits/transitions and writes existing audit evidence. Capability denial is `AuthorizationException`/HTTP403; hidden articles are HTTP404. Invalid lifecycle actions return truthful errors without a success flash.
- `routes/web.php` moves only the existing `/it` hub and KB routes into the knowledge-capable entry group. Author/reviewer grants never open the ticket/provisioning route group. `ItProvisioningController` gives knowledge-only roles a scoped catalogue/options and `summary:null`, with no ticket, provisioning, report, overview or agent directory data. Existing `ItModuleNavigation`, shared permission DTO and app sidebar expose the same destination.
- `index.tsx` uses explicit author/review controls and per-record capabilities, lets reviewers read the current article body, and conceals a reader/editor after refreshed capabilities remove access. KB creation from resolution is offered only to an author. `ItHero` nullable knowledge-only presentation is root-owned.
- `SiteVendorController`, `SiteCredentialController`, `routes/sites.php` check `credentials.audit`; global DTO/menu/history controls use `credentialsAudit`. Audit dialog unmounts on grant loss, aborts obsolete fetches, clears old rows on new fetch and disables cached export during loading/error. Secret controls continue to require reveal authority.
- Changed meaningful fixtures explicitly grant the new authority to the actors performing knowledge lifecycle operations or testing audit Site boundaries; no production role defaults were loosened.
