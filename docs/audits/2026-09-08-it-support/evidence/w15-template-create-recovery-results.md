## Implemented

- A template create carries its originating actor and command UUID. The canonical actor lock serializes creates, recovery and cancellation. A committed receipt points to the canonical template; replay returns the original identity/version receipt without recreating tasks, immutable history or creation audits.
- Contract hashing preserves authored task-array order. Reusing the same UUID for changed content returns a conflict. Recovery and cancellation of a committed result recheck current approved Site access; receipt ownership is not a permanent grant.
- Explicit cancellation before commit retains a tombstone preventing a late original create. Cancellation after commit returns the exact existing result without undoing it. Template/task/version/audit failure rolls back the receipt transaction.
- Migration39 adds the nullable canonical template FK and widens the existing resource name from 16 to 32 characters. Rollback refuses retained template commands or any resource value that would be truncated.
- The shared WizardShell uses the existing setup create recovery hook and controls. Pending work disables edits and repeat saves; Stop waiting retains uncertainty; recovery and exact retry use the same command. The session marker contains only an actor/resource-bound UUID. Expired/denied contexts conceal the private draft. Actor binding also applies to ordinary template edits.
- Focused frontend tests exercise lost-response recovery without a duplicate POST, UUID-only storage, concealment after recovery denial and editable server task-field errors. The existing standalone real-worker setup test is extended to include template create/create and create/cancel races with immutable-version counts; this new extension has not yet run.
