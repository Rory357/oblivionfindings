Implemented and focused-test verified on 9 September 2026. Browser verification is pending the coordinated replacement for superseded Build8. No provider, database, migration, watcher-command or protected design source changed in this slice.

## Current behavior

- `resources/js/hooks/use-ticket-page-refresh.ts` uses the full canonical Inertia GET without an `only`/`except` filter. Fresh `auth`, `viewer_user_id`, linked records, KB suggestions and every scoped option are therefore recomputed together. It checks actor, viewer, ticket and component in `onBeforeUpdate`, before Inertia applies page props. A mismatched identity remains concealed across an incoming scope change and requires explicit full-page navigation after old work is purged.
- The hook correlates `inertia:invalid` responses using one unique header for its own read. An unrelated visit is never intercepted. Confirmed 401/419 triggers session concealment; 403/404 triggers access denial. Neither a failed retry nor a timeout clears an existing concealment state. Only a strict current actor/ticket acknowledgement can restore the session view. No success message is fabricated for an unconfirmed read.
- Concurrent refresh calls use a synchronous request guard. A commit while a read is pending queues one later read rather than dropping that commit's refresh. The original read's late completion cannot finish its successor. Waits remain bounded to 20 seconds, and scope cleanup removes the request-specific event handler and timer.
- `resources/js/pages/it/tickets/show.tsx` requires the canonical viewer ID, conceals the workspace on a failed identity/access proof, and keeps the original Thread actor, capability and record props long enough for root's `accessState` cleanup. Private dialogs and recovery portals stop rendering. After confirmed denial/actor change, the next render removes the stale record DOM; session concealment preserves the mounted composer until a matching check. The generic recovery alert is an approved Alert component with sign-in, check or full-reload actions.
- `resources/js/hooks/use-it-ticket-peek.ts` bounds drawer GETs to 20 seconds, aborts/ignores late data and retains the last authorized snapshot on a network failure. Access state survives a failed retry independently of transport error state. `components/it/ticket-drawer.tsx` retains the same original Thread instance during concealment so root's shared component can retain session work or purge denied work. No private browser storage or alternative ticket read endpoint was added.
- Session-concealed same-scope drawer work retains its dirty/busy guard even while the visible payload is withheld. Reload/tab exit, Close and GET navigation still require the existing generic confirmation. Confirmed access/actor denial removes the guard after purge. The page's generic leave confirmation renders outside the hidden workspace during session concealment so a navigation attempt is not silently blocked.
- Root independently owns the coordinated Thread/composer `accessState` implementation and its dual-audience cleanup tests. Those files are outside this agent's changes and test counts below.
