## Implemented contract and decisions

- `ItSlaClockService::verdict(ticket, at)` is the authoritative, read-only evaluation. It returns `state` (`ok`, `at_risk`, `breached`, `met`, `paused`, `unmeasured`), independent first-response/resolution clocks, coverage (`none`, `partial`, `full`), retained breach evidence and the evaluation timestamp. Missing dates, unknown historical pause calendars and undefined reopened-episode targets do not become healthy compliance.
- `summarize(iterable, at)` consumes an authorized lazy sequence once and returns total, exclusive `by_state`, `by_coverage`, `ever_breached`, each clock's `by_state`, and the common evaluation timestamp. The caller retains authorization/query ownership. Full/partial/absent coverage denominators are separate.
- New tickets snapshot the existing configured response/resolution targets, business calendar, holidays and timezone. Existing code defaults remain unchanged where no policy row exists. Priority changes preserve the creation anchor, original snapshot and prior breach evidence, and append a policy-change event. Reprioritizing an existing unstamped ticket does not fill missing historical clocks.
- Resolution pauses bank working minutes against the recorded calendar. The existing accepted waiting-party options remain explicit in the snapshot: requester, vendor, approver, team, change and other. The public response clock continues during waits. Unknown legacy pause units remain unmeasured after resume. No historical pause conversion was performed.
- A priority change during a live wait now checkpoints elapsed minutes using the old calendar before applying the new one. An invalid/unmeasurable historical pause cannot trap work in waiting; resumption preserves an explicit unknown-accounting marker. New approval waits record the real initial policy rather than being mislabeled as historical gaps. All three persisted cases passed in the focused rerun below.
- BusinessHours honors a snapshot timezone, normalizes overlapping/unordered windows without double counting, handles real elapsed minutes through NZ daylight-saving transitions, and rejects invalid or exhausted calendars instead of inventing a wall-clock fallback. The policy editor rejects targets outside the supported calendar range.
- Canonical public replies retain late first-response outcomes. Generic settlement no longer fabricates a first response; the resolution-with-public-note path records the actual public comment time. Resolved and reopened records retain previous breach evidence. Until W09 defines a new episode policy, reopened resolution remains unmeasured even after another settlement.
- The watchdog evaluates each ticket under its row lock, commits state/history and canonical notification intents together, and drains committed intents afterward. First-response and resolution breaches can each emit once. Missing recipients produce a visible coverage gap; later recovery appends a recovery event and never rewrites the original event.
- Existing cadence is preserved: hourly watchdog, urgent escalation eligibility after 30 minutes from creation/current reopen episode. Current eligible assignee/owner and configured queue cover are considered; fallback admins must also be currently eligible. Approved HR leave prevents selection. Delivery reconstructs the existing `ticket_sla` notification and rechecks current staff eligibility again before dispatch/channel execution.
- Watchdog freshness is separate from ticket clock state. Canonical automation definitions expose last successful execution and `fresh`, `stale`, `failed`, `running` or `unmeasured` evidence. Five minutes of completion grace follows the existing schedule slot. Absent or stuck runs never become green health. The SLA command records its own direct/scheduled result; scheduler event recording excludes a duplicate SLA run.
- `ItAutomationScheduleCatalog::freshnessFor('it.check-sla', optional at)` retrieves only that automation's latest execution and last success. It accepts the integrating request's common timestamp; unknown keys return null. It shares the canonical freshness evaluator and run lookup with the setup catalogue.
- SLA policy grid persistence and audit are atomic. Existing tickets retain their snapshots; policy changes apply to newly stamped clocks through the existing canonical method.
- The intake wizard no longer invents a due date using browser wall time. It shows the supplied target in working minutes only when the supplied business calendar is enabled, otherwise minutes, and states that deadlines are calculated when saved. Triage and final review use the same label. The policy editor describes all six existing accepted pause parties.
