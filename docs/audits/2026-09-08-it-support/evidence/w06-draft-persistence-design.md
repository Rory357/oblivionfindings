# W06 draft persistence prerequisite — read-only design, 2026-09-09

Status: Recommendation only. W05 remains a dependency; no W06 application, schema, configuration or UI implementation was performed. Desktop web acceptance applies under the user's later clarification.

## Sources and confirmed current behavior

Read the exact W06/W07 and section 4 draft/handoff requirements, F09/A06/E01/E06, the repository design rules, and these existing implementations:

- `resources/js/hooks/use-form-autosave.ts` stores the entire form in plaintext localStorage, trusts parsed data, has no revision/access/expiry protocol, and silently ignores storage failures. Do not put IT private text, notes, credentials or attachment metadata through this helper.
- `IncidentReportDraft`, `IncidentReportDraftService`, `IncidentReportDraftController`, its migration, prune job and `use-incident-report-draft.ts` provide the repository's existing secure recovery precedent: encrypted array payload, hidden ciphertext/hash fields, actor/Site binding, revision conflicts, HMAC equality, explicit resume, terminal consumption, no-store JSON and expiry. Its incident/client permissions and routes are domain-specific. It is not a generic storage service for IT.
- Incident draft retention is currently 14 days. Its browser hook keeps only an actor/workflow UUID pointer locally. Reuse the design, while addressing IT's stronger audience/session/unknown-command needs: browser-storage exceptions are not consistently caught there, its GET uses a cancelled flag without aborting HTTP, 403 is generic, and discard deletes a row rather than leaving a delayed-save tombstone. Do not broaden or rewrite incident behavior as part of W06.
- `DraftResumePrompt` and `DraftSavedIndicator` are approved shared display components. Their defaults say "on this device"; a server-backed IT consumer needs a backward-compatible storage-location/description option. The indicator must show acknowledged saved state only, with a distinct recoverable failure message/action.
- Current `TicketThread` has one `body`/file list and toggles `is_internal`; it does not retain independent public/internal drafts. It clears on Inertia `onSuccess`, which can also follow an application error redirect. This is a concrete W07 integration dependency: do not consume a draft on that callback until a committed comment is proven.
- Current `TicketDrawer` visits the full page directly and closes directly on Sheet dismissal. It lacks a navigation draft gate and abort/epoch protection on the ticket GET. Full detail and drawer already share `TicketThread`; extend that composition instead of building another editor.
- Current W02 `useItTicketCommand` retains only an explicitly acknowledged uncertain UUID in `it.pending-ticket-command.v1.actor.{actorId}` sessionStorage. Its frozen payload is memory-only. Restored markers intentionally offer receipt recovery, not editable replay. Generic receipt 404 is not proof of no in-flight commit. This contract must remain intact.
- `ItAttachment` is already a protected polymorphic record on the private disk, and `ItAttachmentStorageService` is the canonical storage writer. A draft attachment parent can extend that existing boundary; do not introduce another upload store or public draft URL.

## Recommended bounded implementation

Add one IT recovery model/service/controller, using the established Laravel encryption and optimistic-revision pattern. A small IT recovery table is justified because no general secure draft table exists; it stores unfinished UI input, not a second ticket or conversation system. Keep actual ticket writes in `ItTicketIntakeService`, replies/resolution in `ItTicketInteractionService`, expected ticket versions in `ItTicketVersionService`, and file records in `ItAttachment`.

Suggested record fields: secure `draft_uuid`, actor ID, immutable operation, canonical ticket ID where applicable, audience, current approved scope IDs, encrypted allowlisted payload, HMAC payload fingerprint, draft revision, base ticket version, saved/expiry timestamps, and terminal consumed/discarded timestamps. Link an intake draft to its existing W02 request UUID separately; a draft identity is not a new submission identity. Use normal organisation-wide/Site authorization; add no tenant context or tenant selector.

The storage uniqueness boundary must include actor + operation + context + audience. Use an explicit non-null context key to avoid MySQL nullable-unique ambiguity: an intake draft identity for create, or canonical ticket ID plus operation for reply/resolve/edit. Browser pointer keys follow the same shape, contain only opaque IDs/revisions, and are never authority. Public/internal audiences have separate records and separate in-memory buffers, even when the same actor can use both. Drawer and full-page composer use the same key; presentation surface must not fragment the draft.

Reserve these purpose contracts rather than a free-form arbitrary-object endpoint: requester intake, technician intake, public reply, internal note, ticket edit and public resolution. Each gets an explicit partial-field allowlist, payload/file-count/size limits and its actual canonical authorization. Partial validation permits unfinished required fields; any selected Site, assignee, asset, Device, service or ticket must already be accessible. An unbound intake draft may contain the actor's unfinished input only while that actor still has creation access; after scope is bound, checking the old binding comes before allowing changes/removing references. Never let clearing a Site or changing audience launder a previously restricted draft.

Recommended HTTP actions:

- Initialize/check context returns only actor-owned draft metadata and current composition capabilities. Do not automatically hydrate old private text into a newly opened form.
- Resume retrieves the exact current revision after reauthorization, then requires the user to choose Resume. Return `Cache-Control: no-store, private`; validate response identity, operation, audience, revision and timestamps on the client.
- Save accepts the expected draft revision and only that purpose's allowed fields. Serialize browser autosaves per key; use row locks/unique constraints server-side. Repeating the same revision/payload after a lost response returns the saved revision. A different stale payload gets a conflict, never last-write-wins.
- Discard is actor-owned, version-aware and idempotent. Stop/settle queued writes and leave a bounded terminal marker so a delayed autosave/initial save cannot recreate discarded work. An unknown save acknowledgement must be reconciled before declaring discard complete. A stale discard cannot delete a newer tab's draft.
- Consume runs in the same canonical transaction as the successful ticket/comment/resolve write, scrubs payload and transfers any approved file parents atomically. A delayed autosave must see the receipt/terminal marker and fail. The established lock ordering is part of the contract: intake already locks actor then receipt; extend consistently to draft/files. Record-edit paths must use one documented ticket/draft ordering across all writers.

No draft text belongs in ordinary logs, analytics, event payloads, local/session storage, Inertia remembered history, browser URLs, search, exports or AI context. Audit metadata records actor, purpose, draft ID/revision and save/resume/discard/consume outcome without body or private values. Avoid auditing each keystroke; save events correspond to persisted revisions. Passwords, tokens, credential values and binary/base64 uploads are prohibited by the draft contracts.

## Full lifecycle and concurrency

Opening shows loading, then either a new blank form or a metadata-only Resume/Discard prompt. Do not autosave initial defaults over an undisclosed stored draft. Resume restores fields/step only after current authorization and explicit choice. Completeness follows meaningful fields, independent of persistence status.

On edit, debounce ordinary saves and retain the latest unsaved buffer in memory. `Saving` refers to a real request. `Saved` applies only to the acknowledged revision/payload; if the user typed during that request, keep the newer buffer marked unsaved and queue it next. Network/500/timeout/cancelled-save leaves an unknown or retryable result with the same revision/payload. Do not advance revision, clear content or invent a saved timestamp. A conflict preserves both this tab's unsaved input and current server metadata; require review before explicit reapply using the returned revision. Base ticket version remains separate, so restoring a draft never authorizes a stale business mutation.

401/419 suspends autosave and conceals the form while retaining any unacknowledged buffer only in actor-bound memory. Sign in in a separate tab, then explicitly recheck identity and current scope before revealing/resuming. The server must bind draft operations to the authenticated owner; a stale page cannot submit its old actor's buffer under a different signed-in actor. A consumed intake draft/owner check provides that binding before canonical create; do not rely solely on stale Inertia auth props. Actor switches, 403 and owned-access-unavailable responses purge visible/pending buffers and pointers without revealing saved text. Server retention does not grant access after revocation. Missing/foreign UUID responses remain indistinguishable; no hidden title is included in a conflict/error.

Workflow blocking is separate from privacy denial. A ticket settling while a reply draft is open must not silently destroy the actor's allowed text. Return current read/edit/submit capabilities and the actual blocker; preserve allowed draft recovery, but canonical comment/reopen rules still determine whether it can be sent. Internal access loss never falls back to displaying that draft as public. Merge/context changes require explicit review against the authorized canonical record; do not silently copy a private draft to a different subject.

Escape, backdrop, close controls and the drawer's Open ticket action route through one draft lifecycle coordinator. Offer Keep editing, Save draft and leave, or explicit Discard as appropriate. Leave only after a confirmed save/discard; otherwise retain work and expose retry. Ordinary Inertia navigation can be intercepted before visiting and replayed once after that decision. Browser history navigation cannot be assumed cancellable through the same event: retain the latest actor-bound buffer in an IT-level in-memory coordinator across page unmount, flush on handoff where possible, and recover it explicitly on return. Full document reload/close uses the native beforeunload protection while unsaved/unknown work exists; do not rely on an asynchronous unload save. Do not serialize private drafts into history.state. Test actual Back/Forward and drawer handoff, not only onClose.

For files, stage through the existing private attachment service with an actor-owned draft parent and explicit temporary lifecycle, not localStorage. Downloads/previews reauthorize draft owner, current Site/ticket and audience on every request. On consume, reparent existing canonical attachment IDs under the same transaction and preserve unknown-commit cleanup protections from W02. On discard/expiry, delete only confirmed draft-owned unconsumed files; failed deletion remains tracked for retry. Scanner/quarantine rules are completed in W07. Until staged files are durable, show that fact and prevent a silent file-losing leave; a filename-only recovery list is not evidence the file was saved.

## W02 uncertain-command coexistence

Check the existing actor-scoped pending-command marker before offering an editable intake draft. If the command may have committed, suspend draft autosave/edit/consume/discard until receipt recovery or the existing explicit acknowledged abandonment choice. Never map generic recovery 404 to a new UUID or fresh submission. In-session retry keeps the original frozen payload/UUID. If W06 later supports retry after reload, it must reconstruct the exact submitted snapshot and staged-file content under that same UUID, with a server-verified immutable submission hash; a mutable latest draft is insufficient. The smaller safe implementation retains W02's reference-only recovery on uncertain close and does not advertise restored payload retry until that stronger contract is implemented.

A confirmed create consumes only its linked submitted draft revision. A retry/late save cannot resurrect it. Consuming a public comment draft cannot erase a separately saved internal note or another tab's later revision. The command receipt remains the authority for whether a ticket exists; the draft never claims cancellation/rollback of an uncertain ticket write.

## Decisions and dependency gates

W05 navigation/list completion is the implementation gate. W06 can reuse W02 identity/version/denial primitives and W01 privacy now; comment acknowledgement/idempotent consumption and staged-file scanner lifecycle must be integrated with W07 rather than marked finished from create-only tests.

Retention, terminal-marker lifetime and prune/recovery ownership are operational choices under DP07. The existing incident service's 14 days is a concrete conservative precedent to propose, not an automatically approved IT retention policy. Record the chosen expiry and cleanup schedule before enabling persistent IT drafts; do not silently choose indefinite retention or claim expired-file cleanup verified without exercising it. Pending decisions do not block the pure contracts, UI guards, authorization and isolated tests.
