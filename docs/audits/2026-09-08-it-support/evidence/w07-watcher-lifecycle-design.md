Confirmed gaps addressed:

- Canonical self watch/unwatch checks work access against the supplied actor without refreshing approval and permission relations under a user lock.
- Intake permits any approved same-Site staff member as a watcher, including an unrelated requester-only account which cannot read the resulting ticket.
- There is no post-intake add/remove eligible-watcher API or UI.
- Queued agent-side public-reply delivery rechecks current ticket access but does not recheck whether the recipient remains the assignee or a watcher. Removing a watcher must stop a still-queued watcher delivery, subject to the existing honest handling of already-sending/unknown outcomes.

Implemented canonical integration:

- Add one current recipient eligibility predicate on `ItWorkAccessService`: approved internal staff with an existing IT entry capability and current canonical `canView`. It never treats watcher membership as access. Reuse this after canonical intake has produced the ticket and for watcher options/additions.
- Extend `ItTicketInteractionService` with an idempotent desired-state setter. Lock ticket, then actor/target User rows in sorted ID order; reload approval/permissions. Retain current per-record `canWork` for administering watchers and self watch/unwatch. Removal permits cleaning up a now-ineligible member. An actual change advances the ticket version and records one event and one integrity-sensitive audit in the transaction.
- New `PATCH /it/tickets/{ticket}/watchers/{watcherUserId}` accepts `{actor_user_id,expected_version,watching}`. Exact success is `{status:'committed',data:{id,viewer_user_id,watcher_user_id,watching,changed,lock_version}}`. Same desired state is a no-op ACK; an opposite stale write conflicts. A lost ACK must be reviewed/retried with the original identity and version, never inferred from a redirect.
- Show/drawer adds `can.manageWatchers`, `watcherOptions:[{id,name}]` only for authorized per-record workers, and per-row `receives_updates` only for that audience. Participant-only technicians retain public visibility without internal controls or eligibility metadata. Existing watcher names remain the canonical membership records.
- Existing `/watch` and `/unwatch` adapters delegate to the same setter; the new browser controls use the original-actor PATCH contract, including self watch/unwatch.
- Recheck assignee/current-watcher membership for existing `ticket_replied`/`agent_side` and `ticket_reopened` audiences, and current membership for `ticket_resolved`/`watcher`, before both channels and retry. Removing a watcher stops matching still-queued intents in the membership transaction; a mail claim that already won retains its sending/unknown outcome. Accepted/provider evidence and earlier database notifications are preserved. Requester resolution and current assignee reply/reopen audiences remain independently entitled. Reopen copy describes the ticket truthfully without calling every watcher an assignee. Existing access tests now use a genuine watcher/assignee fixture before testing revocation.

Transport/error details:

- A changed ACK advances `lock_version`; an already-achieved desired state returns `changed:false` with the current version. A future supplied version is never accepted as a no-op. A stale opposite proposal returns `409 stale_ticket` with the existing safe current-record/version reference.
- Missing actor/version/boolean returns 422. Actor change or loss of per-record work access returns 403; hidden tickets or absent target accounts return 404; an ineligible addition or merged original returns a generic `watcher_user_id` 422 error. No target name is exposed in those errors.
- `GET /it/tickets/{id}` is the existing authorized review, with top-level `viewer_user_id`. `can.manageWatchers` is current per-record work access and an unmerged ticket. Resolved/closed tickets retain subscriptions; merged originals reject mutations. Requesters and participant-only technicians do not acquire self-watch or administration permission.
- Events use `{user_id,self,watcher_name}`. Historical events lacking `self` remain historical evidence; no audit backfill is performed.
