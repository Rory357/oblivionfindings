# W11 private attachment staging

11 September 2026. Backend staging foundation implemented and verified by the focused tests below. Full W11, E10 and the goal remain incomplete.

## Scope and implementation

This slice supports W11 bounded protected attachments, F03/F05, B01/B02 and E05/E10. It does not close those findings/scenarios. Existing canonical `ItAttachment` records are associated with `ItInboundEmail` during preparation, using the existing private local disk and opaque UUID paths. The existing ticket download controller denies this parent type, including for an administrator. No new attachment store, ticket system, organisation selector or permission grant was introduced.

Migration `2026_09_11_000019_add_it_inbound_attachment_staging.php` adds immutable manifest/count evidence to inbound receipts and bounded position/content hash/storage/scan metadata to attachments. A unique canonical parent/position prevents duplicate reservations. Downward migration refuses to discard existing inbound staging evidence. Migration19, like17/18, has NOT been applied to the working database.

`ItInboundAttachmentStaging` commits the full reservation before downloads and commits each byte fingerprint before physical writes. Provider download callbacks run outside database transactions. Writes/scans take the current mailbox claim and receipt/file locks; disconnected/reconfigured or completed receipts cannot acquire delayed writes. A required audit failure leaves a tracked reservation; a committed result with lost acknowledgement retains ready bytes. Replays validate immutable manifest/content and preserve the same records.

Detected file type and the canonical upload allowlist are checked before the shared `MalwareScanner`. Missing/failed scanners leave retryable preparation; infected and disallowed files remain private and rejected. Attempt time and completed-scan time are distinct. Config provides IT-specific executable/name/timeout integration points; no executable or live provider was selected. Clean/infected test verdicts are explicit synthetic fixtures. Missing-executable verification calls the real shared adapter.

`filesForIngestion` requires an owning current claim transaction and rechecks complete, clean, unchanged private bytes. It returns canonical `UploadedFile` inputs for the later integration with existing intake/reply commands. It does not itself authorize a sender or create a public attachment. `finish` marks accepted temporary copies disposable in the owning receipt transaction; cleanup only removes committed processed/duplicate copies and verifies absence before recording completion. Quarantined content is excluded from mechanical cleanup. Its retention/review policy is still DP07 work.

Changed source: new staging service, retryable exception, migration19 and standalone lifecycle test; existing `ItEmailAttachments::validateBatch` exposed defensively; canonical attachment/inbound models, morph map and IT configuration extended. Explicit standalone W27 command documented in `tests/Concurrency/It/README.md`.
