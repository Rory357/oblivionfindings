# W15 catalogue attachments — working evidence

This is a partial W15 implementation record. Catalogue drafts, complete provisioning, historical internal-answer remediation and final package/release acceptance remain open. Production scanner, provider delivery and AI execution are not claimed.

## Current source

Catalogue attachment fields use the existing private `ItAttachment` records, storage reservation ledger and owning transaction context. Each saved file belongs to the immutable `ItCatalogSubmission` and its original field key. Current ticket or provisioning authority is rechecked for each protected download and file projection. A withdrawn form does not erase submitted evidence; missing original fields and lost result access deny disclosure. Ticket participants and provisioning beneficiaries receive only public evidence. Internal files are labelled for eligible technicians.

The authoring UI offers attachment fields with bounded file counts. The desktop request wizard selects actual files, validates extensions/size/count, preserves selected files on Back and rejected additions, removes files with focus recovery, and reviews names and sizes. Submission switches to multipart only when needed. Exact retries retain the frozen file objects and request identity. Browser session storage holds only recovery identity; it cannot restore missing bytes after remount.

The additive migration retains `catalogue_field_key`; rollback refuses to remove audience evidence once files use it. The existing morph map, storage service and storage-intent model admit canonical catalogue submissions. An initial missing model allowlist entry was found and corrected before passing claims. A subsequent server guard prevents required attachment fields from collectively demanding more than five files, on save and publication; its feature regression is pending.
