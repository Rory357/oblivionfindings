## Implementation

- Catalogue ticket creation delegates to ItTicketIntakeService. The canonical service rechecks the locked immutable publication, current actor and Site, then derives service/outcome/approval/classification from that publication. Ordinary intake cannot acquire catalogue privileges through posted fields. One created event keeps catalogue/version provenance. SLA, routing, priority assessment, creation audit and durable notification intent use the canonical path.
- ItCatalogSubmission remains the command's canonical idempotency owner; no duplicate creation ledger is added. Its outer transaction is now the existing ItAttachmentWriteContext, ready to own eventual file reservations. Controller notification execution is replaced by best-effort post-response dispatch of committed outbox intents; scheduling failure cannot change the saved result. Scheduled drain remains the recovery path.
- Requested-for is separate from submitter/requester. Only IT management may select another eligible person, checked against canonical current staff/Site scope. Provisioning also validates the canonical employee profile and prevents mismatching an explicitly selected person with an employee field. Requested-for participates in the submission fingerprint, and general canonical command fingerprints include it only when present so old receipts retain their meaning.
- New HTTP submissions require UUIDs accepted by recovery/cancellation. Previously committed legacy records are retained; trusted direct-service legacy keys are not rewritten. New HTTP free-text keys and explicit unfinished requested-for choices are rejected before creating work.
- The approved request wizard reuses CatalogueEntityPicker for requested-for. Its dedicated read endpoint uses the existing directory and intake eligibility, binds actor/publication/query/Site/selected identity and returns private/no-store responses. Server capability controls visibility. Site changes clear the chosen person. Review uses the actual selected name. Retry retains the exact person and command in RAM; browser storage contains identity metadata only. Lookup session expiry with an unfinished person choice retains explicit null and cannot silently become a self-request.
