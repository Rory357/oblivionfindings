New sequential tests and actual two-worker capacity/name races verify this final follow-up.
- **F09/F11/F15 / W05 / E04/E06 — bulk outcomes:** canonical, individually locked writes now return per-selected-ID outcomes. No hidden record title, reference, exception payload, current version, internal reason or link enters a receipt. Missing, inaccessible, participant-only and revoked records have the same `unavailable` message. Stale rows request reload/review, blocked rows request inspection of current requirements, failed writes are reported server-side and retain generic recovery copy. A rolled-back failure does not prevent successful siblings. Existing routing/priority reasons and expected-version maps remain required.
- Both bulk requests require 1–50 distinct positive IDs. An explicit null ticket assignee is supported with its required routing reason; omission remains invalid. Provisioning still requires a real technician. All unchanged uses an info flash; any rejection uses warning; a success flash requires an actual update without rejection. JSON callers receive the same result data. A session result is projected only for the actor who performed it.
- **W01/W05 — provisioning revocation:** the locked canonical provisioning guard reloads the actor before checking permissions and uses an authorization exception for access denial. A regression revokes `it.manage` after the first batch write; the second item stays unchanged and reports `unavailable`.
- **F07/F10/F11 / W05 / E04 — actionable views:** preserve every existing view/deep-link key and add `unowned`, `waiting_requester`, `waiting_vendor`, `waiting_approver`, and `unmeasured`. Unowned means open work with no accountable `owner_user_id`, distinct from individual assignee. Wait views use the stored exact waiting party. The new private ownership/waiting views require the same canonical manage audience as `canWork`; their counts and rows both exclude participant-only and read-only actors. `applyWorkScope` shares the existing staff query branch rather than creating a second policy. Unmeasured uses current SLA evidence for open work, including partial coverage, and excludes settled unknown history. The legacy `awaiting_reply` label is now “Awaiting first reply”; W07 still owns the real latest-conversation/next-speaker “Awaiting IT” contract.

## UI integration contract

`bulkResult` is null unless a current actor has an agent payload and owns the flash receipt. Otherwise it has `resource` (`tickets` or `provisioning`), `action`, `selected`, `updated`, `unchanged`, `rejected`, and `items`. Items preserve input order and contain only `id`, `status`, and `message`; statuses are `updated`, `unchanged`, `stale`, `unavailable`, `blocked`, `failed`. JSON is `{message, result}` with that same result. Reload current authorized rows before choosing to retry; never silently substitute newer versions and resubmit rejected rows. Existing per-row selection and version contracts remain authoritative.

The UI agent owns list/nav/card/table/search/count and outcome rendering; this backend slice made no TSX edits. Provisioning list and CSV continue to support exactly status/type/assignee. Requester scoped search/status filtering can operate on the complete authorized My requests dataset. Do not show an active provisioning free-text search until its backend contract exists.
