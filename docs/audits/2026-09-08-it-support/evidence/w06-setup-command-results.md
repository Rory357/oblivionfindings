## Implemented contract

New Team, Queue and Service wizards submit JSON to the existing canonical create endpoints with an original actor ID and a UUID. `ItSetupCommandService` locks the current actor, rechecks approval/permission, and atomically commits the dedicated receipt, existing canonical setup record and required audit. Actor+UUID is unique across Setup resources. Same UUID and body replay the exact result; changed payload/resource returns409. Replaying after an independent record edit preserves that edit and returns both original committed and current configuration hashes. Recovery rechecks current record/binding authorization and does not echo entered values.

`POST /it/setup/commands/{uuid}/recover` returns actor/resource/UUID-bound `committed`, `not_found` or `cancelled` metadata. `not_found` does not authorize changing the uncertain command. `POST /it/setup/commands/{uuid}/cancel` serializes on the same actor: a committed result is returned unchanged, or a cancellation tombstone is durably recorded and audited so a late original create cannot write. Cancellation is explicit; cancelling a wait merely stops waiting. Tombstones have no request hash or record foreign key. The nullable hash is not used for committed creates.

The browser stores only the opaque original command UUID in actor/resource-scoped session storage immediately before send. Exact submitted fields remain in RAM. A matching terminal acknowledgement removes the marker with compare-and-remove semantics. A competing unresolved marker wins over a new create. A first definitive422 permits correction and advances the RAM settlement token; a422 after an unknown attempt cannot disprove that earlier commit. Session expiry conceals entered values, denial purges the current copy, and wrong-actor/malformed/late results never acknowledge success. Explicit fresh candidate authorization precedes native-traversal Resume; an empty reloaded marker can recover only its matching original RAM command, without consuming a different proposal.

Setup RAM preserves whole canonical base/proposed fields, selected-binding history, step, original configuration version and exact unknown submitted snapshot. The current-form owner cannot erase an independent same-context copy. A proven terminal command may clear copies of only that actor/resource/command UUID. The reviewed20-copy/64MiB ceiling is a local resource bound with no eviction or invented retention policy; capacity errors are actionable. Unsaved copies register an unload warning but do not write on unload. All private entered values remain out of browser storage/history.
