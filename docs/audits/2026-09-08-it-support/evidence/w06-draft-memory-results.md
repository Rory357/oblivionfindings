## Contract

`createItDraftMemoryStore({maxEntries,maxBytes})` maintains only document-lifetime RAM. No localStorage, sessionStorage, IndexedDB, Inertia remembered content, network request, timer or automatic save is introduced. Each candidate binds original actor, purpose/audience context, canonical draft UUID and revision, latest typed snapshot/base ticket version, optional original pending save snapshot/revision, optional original selected File/upload UUID/revision, and an unknown-outcome flag. Payloads are cloned and allowlisted; File objects retain their exact immutable identity without copying bytes or inventing a saved attachment.

`retain(candidate, bufferId?)` creates a distinct opaque buffer or updates that exact buffer within the same actor/context/generation. It returns an explicit invalid/capacity/scope-changed/frozen result on failure and preserves existing work. While an outcome is unknown, newer local text may be retained separately, but the original revision, unknown flag and pending save/upload intent cannot change. Caller integration must update retention continuously while mounted and show capacity failure before navigation; cleanup-only retention cannot provide that warning. `discardBuffer` removes only a deliberately selected local buffer and never claims to discard the canonical server draft.

`discover(actor, context)` returns only buffer ID, generation/revision and pending/unknown flags. It returns no text, filenames, private paths or File objects. Foreign actor/ticket/audience discovery and authorization do not reveal or delete the other buffer.

`authorizeResume(bufferId, binding, callback)` is invoked only after explicit Resume. It gives the internal authorization callback a private candidate copy and a fresh secure nonce. Root's new canonical `/it/drafts/{uuid}/validate-candidate` seam must check current actor/purpose/record and the latest candidate's selected bindings. The helper accepts only HTTP200 with the exact nonce, actor, canonical purpose/context/generation, expected authorization revision and base ticket version, plus currently readable active canonical metadata. Mismatched/malformed/non200 results yield no permit;403-style denial purges the exact candidate, while session expiry, conflict or transport failure retain it concealed. The callback must classify the actual status honestly.

The optional `explicitlyReviewedRevision` binding is permitted only after the host has shown the actual saved revision and the user has explicitly adopted that review. It changes the revision used to authorize the local candidate; it does not change the adopted original retry revision, pending save/upload revision or base ticket version. Without that deliberate review, a newer server revision fails closed.

Successful authorization returns an opaque one-use permit, not the private payload. `adopt(permit,binding)` checks the same current scope and buffer sequence, then atomically returns/removes that exact candidate immediately before host adoption. Updated snapshots, another authorization, actor purge or generation removal invalidate stale permits/results. The pending save remains opaque inside the hook for exact canonical retry; it must never replace the latest host text. Current scope checks still run on that retry.

`purgeActor`, `purgeContext`, `purgeGeneration` and `clear` support current actor/access/logout/deactivation/terminal cleanup. `acknowledgeConsumed` removes only an exact acknowledged generation/revision/snapshot; newer local text and another generation remain distinct. Integration owns when these methods are called and must not infer current access from cached Inertia props.

## Persistence-disabled recovery and adapter

The adapter continuously retains each committed render in a layout effect and captures the final committed snapshot during cleanup. It starts no request during unmount. The active owner map excludes still-mounted sibling forms from recovery notices. Changed actor clears old actor content; stale request epochs cannot return it. Explicit Resume uses a cancellable, timed request and never automatically saves or adopts content. Cancel stops only the wait, ignores late responses and keeps the copy available.

When persistence is enabled and an active canonical row exists, recovery first validates the exact latest candidate through `/it/drafts/{uuid}/validate-candidate`, then performs canonical `/resume` and checks the same generation/revision, typed payload and file DTOs before atomic adoption. Original base version and pending retry snapshot remain separate from freshly read metadata. The optional `settledOperationToken` advances only on a definitive response to the mounted frozen operation. It allows a known 422 rejection or validated acknowledgement to release that one frozen buffer without incorrectly using an older successful save as proof or discarding abandoned sibling work.

When persistent drafts are disabled or no canonical draft exists, a distinct `kind: memory` generation holds typed fields, original base version and every original selected File (maximum five, accounted within the same byte ceiling). It invents no draft row, revision, expiry, saved file or upload identity. Explicit Resume calls only `/it/drafts/validate-local-candidate`; HTTP200 proof must match the nonce, actor, purpose/context and memory generation. Its strict safe DTO carries current submit capability and blockers without adopting a current ticket version. The returned `serverResumed` is null. Parent implements that permission-only endpoint without the persistence activation gate.

Both branches retain up to 100 distinct canonical scope bindings, including A → B → cleared selection history. Every prior scope is sent for independent current authorization. Exceeding the scope or byte/count bound warns while the form remains mounted and preserves prior work; it never evicts another buffer. Metadata-only intake UUID discovery permits a host to find the correct local request context after Back, with the existing pending W02 command marker taking precedence. File names and content are excluded from notices.

## Integrated checkpoint

Resolve passes its current typed snapshot, dirty state, unknown canonical outcome, definitive response token and supported field names to the shared draft hook. Recovery controls remain available with persistence disabled. The restored original ticket version is preserved; an uncertain resolution or stale/settled blocker requires a current actor-bound ticket read and deliberate reapply. A later current version is accepted only after that explicit review. Known 422 keeps the failed text recoverable. Confirmed success and explicit current-form discard clear only that form's memory, preserving independent same-context editors. Access loss may clear the whole authorized context.

The adapter suppresses an explicitly cleared exact snapshot/File identity during immediate unmount, preventing discarded content from being retained again. An old still-mounted actor cannot republish its data when a newer actor becomes current. Initial local-to-persisted handoff atomically replaces the mounted copy at the existing capacity cost and restores it on validation/capacity rejection, avoiding an abandoned stale initialization copy. Independently abandoned buffers are unchanged.

Matching-editor compatibility is checked before adoption: supported field names and selected-file mode are explicit host contracts. Value predicates see cloned snapshots only after strict current authorization succeeds, and test both latest fields and any frozen pending-save snapshot. Rejection preserves the original buffer and explains that it needs the matching editor. If a file-bearing local copy was created while persistence was disabled and the effective setting later becomes enabled, the staged-file intake cannot silently hide or drop those original Files: restoration fails closed before adoption. Transferring that copy into the new staging mode is an explicit remaining compatibility/recovery dependency, not a completed file-transfer feature.
