# W15 catalogue request command and wizard lifecycle

12 September 2026. Implemented; current browser verification remains pending. Mappings: W15, W01/W02/W06, E01/E06/E14. Whole packages/scenarios and release gate remain open.

The requester now uses the approved WizardShell, separate details/review, real selected-Site and entity labels, required-field validation, keyboard focus, explicit dirty/navigation confirmation and confirmed-result success. The typed JSON transport binds actor, item, original schema and UUID. Lost responses preserve the original frozen payload; check/retry/cancel never silently create a new identity. Session/access denial conceals private request and catalogue content. Session restoration checks the original result without resending fields. Browser storage retains identity metadata only. New submissions fail before sending when that storage is unavailable; recovery warnings distinguish retained identity from unavailable storage.

Cancellation reuses ItTicketCommandReceipt as an actor-bound tombstone under the same actor mutex as ItCatalogSubmission. A committed canonical submission wins and is never undone. A cancelled identity refuses late submissions. Withdrawn publications permit cancellation against their retained immutable audience; they remain unavailable for discovery/new intake, and never-published or restricted drafts remain denied. No new ledger, ticketing system or migration was introduced.

## Confirmed next integration dependency

Focused source review while the wizard builds: ItTicketIntakeService::createCommand already owns atomic ticket creation, audit and prepared outbox deliveries. Its current browser actor policy deliberately forces requester work_type=incident, ignores requester it_service_id, and derives approval from category. A naive replacement of the catalogue writer would therefore lose the published service/outcome/approval contract. Extend the canonical intake with an explicit trusted catalogue contract, rechecking the immutable publication and current actor/Site, without accepting a browser-supplied permission override. Preserve catalogue provenance in created events and command fingerprints; remove the controller's separate post-commit notification send once canonical preparation owns it. The existing requested-for field is currently set equal to requester, so preserve creator/requester/requested-for meaning through the explicit permitted-person contract rather than relabelling IDs.

For later attachment fields, ItAttachmentWriteContext already carries direct storage reservations to the outermost commit owner and protects files after uncertain acknowledgement. Catalogue submission must own that context when its submission row commits outside nested ticket intake; do not create another cleanup service. ItTicketDraftPurpose currently has intake/reply/edit/resolution purposes but no catalogue binding. Extend canonical drafts with actor/item/publication scope and reuse storage/retention controls, preserving production-disabled retention until its operational decision. These are identified next actions, not implemented or verified claims.
