# W13 service identity lifecycle

11 September 2026. Implementation and verification are in progress. This bounded slice maps to W13 and the identity portion of E12. Full W13, E12, Operations recovery and the release gate remain incomplete.

## Implemented

- Canonical service identities now have a configuration version distinct from authentication usage timestamps. Dedicated nonsecret command receipts cover issue, grant update, rotation, revocation, recovery and cancellation. Actor, creator and public identity remain immutable.
- JSON-only management routes return a credential only in the original confirmed issue/rotation response. No reusable credential is placed in session flash, Inertia props, receipt storage, list responses or recovery results. Lost acknowledgements recover the existing outcome without a second rotation or redisclosing the secret.
- Commands recheck current manager, execution account, permission and approved Site evidence under ordered locks. Identity changes serialize with API publication. Revocation, expiry, rotated hashes and removed capabilities are rechecked before an authenticated request can publish work.
- Grant edits reject stale configuration versions. Expired, unrevoked identities may be explicitly extended or revoked; rotation requires an active identity. Cancellation creates an actor-bound tombstone only for an uncommitted command and does not undo a committed identity change.
- The existing Setup API identity register now uses the approved shared wizard for issue and edit, with capability/field/Site review, explicit stale-grant adoption, one-time credential clearing, clipboard failure feedback, account-change concealment and same-command recovery. Parent review and automated UI verification are complete; actual browser acceptance remains pending.
