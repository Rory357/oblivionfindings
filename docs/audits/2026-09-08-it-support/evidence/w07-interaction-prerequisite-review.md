# W07 focused implementation handoff

Read-only source review on 9 September 2026 while the W06 shared recovery contract was being completed. This is not a new audit or a completion claim. W07 implementation follows the W06 form contract and remains required in full.

Confirmed current gaps:

- `ItTicketController::storeComment` writes through `ItTicketInteractionService`, then sends notifications outside the comment transaction and returns an Inertia success flash saying “Reply sent.” A failed notification and an unconfirmed command need a separate persisted delivery outcome and retry path. Reuse the W02 canonical command receipt/outbox conventions and `ItEmailDeliveryService`; do not introduce a second message store.
- `StoreTicketCommentRequest` has no original browser actor, command UUID, expected ticket version or draft consumption contract. Extend its existing public/internal authorization, protected attachment rules and canonical interaction boundary. The new client must preserve the exact uncertain command and require a matching JSON acknowledgement before clearing text/files.
- `ItTicketInteractionService::addComment` serializes against settlement but calculates requester identity only from requester_user_id, and first response from agent capability alone. Define actor-as-requester behavior consistently with the display and channel adapters; internal notes must never count as public agent responses or end a requester wait.
- `ItProvisioningController` list filter and summary SQL still define awaiting_reply from first_responded_at being null; `ItSavedTicketFilterService` still calls it “Awaiting first reply.” Replace this proxy with the same canonical last-public-speaker/next-responsible-party projection across conversation, list, meters, saved views and later reports. Preserve first-response SLA evidence independently.
- Watcher interaction currently covers self watch/unwatch. Eligible add/remove lifecycle, current Site/record restrictions and revoked-recipient checks still need full W07 implementation and browser evidence.
- `ItAttachmentStorageService` uses private canonical ItAttachment storage and protected download routes, but no IT scanner/quarantine lifecycle was found. Draft upload staging is storage reliability, not malware verification. Add truthful scan states and failure/retry integration through the actual approved scanning capability; keep any missing provider verification explicit.

Reuse the W06 public_reply/internal_note purpose separation, original actor checks, encrypted draft and staged ItAttachment contracts, and document-memory recovery. Do not store private composer content in browser storage or automatically switch audiences while restoring. Root full-page leave guard and the drawer guard currently expose only dirty/busy metadata; this does not yet prove native Back recovery for the W07 composer.

Required focused evidence: public agent response → later requester response returns to Awaiting IT; internal note leaves that state unchanged; ambiguous command retry creates one comment/outbox intent; notification failure does not lose a committed comment; upload failure/quarantine preserves text; copied internal/download URLs and revoked watcher access fail closed; settled/merged ticket rejects ungoverned replies without clearing the composer. Real provider delivery remains subject to DP07, W11 and W12.
