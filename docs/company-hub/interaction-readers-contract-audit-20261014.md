# Approved reader interactions: backend and contract handoff

Read-only review, 14 October 2026. Covers families **11–16, 19–23, 36–37** in the approved interaction collection. Approval was confirmed by the parent implementation session; this supersedes older delivery notes describing that collection as awaiting approval. No application files, migrations or live records were changed, and no tests were launched for this audit.

The effective design is the base family source **plus its later overlays**: [build order](interaction-mockups/build.ps1#L23), [journey refinements](interaction-mockups/journey-finish.js#L23), and [connected browsing](interaction-mockups/connected.js#L1). The [README](interaction-mockups/README.md) expressly says these actions mutate fictional local memory, not a production backend. Sample names, counts, reviewed dates, local save messages and prototype check files establish design intent only.

**Status vocabulary:** “implemented and verified” below means a matching backend contract has recorded passing application tests. It does not certify every new connected browser journey. “Implemented but unverified” identifies current source without matching terminal journey evidence. “Missing” means the approved action or required contract is absent, even if a related older feature exists. News/resource interface integration is being completed independently by root; this review does not label that ongoing work finished.

## Material gaps, in implementation order

1. **Complete nested return journeys (client contract; no new persistence needed).** Approved [connected.js:8–20](interaction-mockups/connected.js#L8) preserves a navigation trail and each originating search/filter/layout/scroll/focus; [lines 103–115](interaction-mockups/connected.js#L103) restores the previous reader, including resource → owner profile → resource → filtered resources. Current [_browse-state.tsx:5](../../resources/js/pages/company-hub/_browse-state.tsx#L5) supports one bounded return snapshot for **news/resources/pages**, with list return tests at [reader-discovery.test.tsx:390](../../resources/js/pages/company-hub/reader-discovery.test.tsx#L390). It is not a nested reader trail. Owner/profile and related-reader links in [_knowledge.tsx:285](../../resources/js/pages/company-hub/_knowledge.tsx#L285) and [line 446](../../resources/js/pages/company-hub/_knowledge.tsx#L446) use plain destinations; People links at [_people.tsx:44](../../resources/js/pages/company-hub/_people.tsx#L44) do likewise. No corresponding memory exists for People, Teams, saved/activity or grouped search. Preserve bounded presentation context through child readers; never turn a return token into authorization or an arbitrary redirect. Explicitly verify the approved reload-reset behavior, not only copied-link restoration. Backend canonical readers already reauthorize every destination.

2. **Shared collection authoring is missing.** Approved [reading.js:19–20](interaction-mockups/reading.js#L19) has editor **Create collection / Rename / Save collection**, while [connected.js:37–39](interaction-mockups/connected.js#L37) lists collections with their resource counts and filters by membership. Current [HubContent.php:104](../../app/Domain/CompanyHub/Services/HubContent.php#L104) accepts only a per-page nullable `collection` string; [HubFeed.php:82](../../app/Domain/CompanyHub/Services/HubFeed.php#L82) projects that label; [_resource-library.tsx:80](../../resources/js/pages/company-hub/_resource-library.tsx#L80) derives groups from published labels. The editor can relabel an individual draft, but there is no shared collection identity/list, creation/rename API or authoring DTO. A label input is not the approved collection journey. Before implementation, settle stable identity, membership and publication semantics; renaming must not rewrite immutable published/history snapshots or expose unauthorized members. The approved source does **not** establish deletion, ordering or a specific new schema.

3. **A correction reporter cannot return to their report and read the owner response.** Approved [journey-finish.js:23–27](interaction-mockups/journey-finish.js#L23) retains the report/status/response across reader and owner views; [reading.js:6](interaction-mockups/reading.js#L6) includes a next review date. Current [HubResourceController.php:14](../../app/Http/Controllers/CompanyHub/HubResourceController.php#L14) saves revision-bound reports but returns only `{saved:true}`. Resolution at [line 31](../../app/Http/Controllers/CompanyHub/HubResourceController.php#L31) is versioned and audited; only the editor workspace exposes reports ([HubEditorial.php:21](../../app/Domain/CompanyHub/Services/HubEditorial.php#L21)). There is no own-report reader projection/read API, response return journey, or owner-routing notification. Its resolve payload has no next-review-date field; changing that date currently requires the ordinary saved-draft/publication flow. Add only the reporter's authorized own report/status/response when this slice is implemented, keep other reports private, and do not silently publish a guide revision from “resolve”.

4. **Notification preferences differ materially from the approved contract.** [personal.js:5–6](interaction-mockups/personal.js#L5) offers recognition, conversation replies, event changes/reminders and **news from followed topics/teams**; required reading remains in Needs attention. Current [HubPersonalController.php:17](../../app/Http/Controllers/CompanyHub/HubPersonalController.php#L17) stores only `news`/`reviews`, and [_dialogs.tsx:32](../../resources/js/pages/company-hub/_dialogs.tsx#L32) displays those two. [HubNotices.php:22](../../app/Domain/CompanyHub/Services/HubNotices.php#L22) sends eligible news to all current authorized recipients with news enabled, without intersecting their followed topics/teams. Existing canonical recognition/reply notifications ([KudosReceivedNotification.php:34](../../app/Domain/Hr/Notifications/KudosReceivedNotification.php#L34), [FeedReplyNotification.php:36](../../app/Domain/Hr/Notifications/FeedReplyNotification.php#L36)) do not consume those Hub toggles. Event notifications remain canonical calendar behavior. Four decorative switches would be false parity: persist and enforce preferences in existing delivery paths, preserve required-read obligations and current role/site/privacy checks, and distinguish the existing editor review reminder.

5. **Process resources with personal steps are not supported by the current checklist contract.** The approved Process example has `steps` ([connected-data.js:21](interaction-mockups/connected-data.js#L21)); [connected.js:45–46](interaction-mockups/connected.js#L45) renders and remembers any resource's steps independently. `Process` is accepted and readable, but [HubKnowledge.php:57](../../app/Domain/CompanyHub/Services/HubKnowledge.php#L57) and [line 81](../../app/Domain/CompanyHub/Services/HubKnowledge.php#L81) expose/write personal progress only when `resource_type === 'Checklist'`; [_knowledge.tsx:334](../../resources/js/pages/company-hub/_knowledge.tsx#L334) matches that restriction. A Process label alone does not enable the approved example. Resolve whether authored personal steps are type-independent or whether this example must be represented as Checklist; retain actor/revision/instruction-key checks either way. No change was made here.

6. **Search preview is a missing interface journey, not a missing all-content backend search.** [journey-finish.js:30–32](interaction-mockups/journey-finish.js#L30) has inline expandable previews and typed Guide/People/Event/Story results. The whole-Hub search already projects authorized pages/resources/people/services/events/recognition/ideas/announcements through [HubController.php:85](../../app/Http/Controllers/CompanyHub/HubController.php#L85) and [_search.tsx:47](../../resources/js/pages/company-hub/_search.tsx#L47), with real summaries and destinations. Current result controls have no Preview/Hide preview, and guides/team spaces share the Stories & pages group. Safe existing summaries and `kind/resource_type` can support the presentation without loading private full records. The separate bounded [HubCommandSearch](../../app/Domain/CompanyHub/Services/HubCommandSearch.php#L13) intentionally contains pages, people and services; do not mistake it for the existing whole-Hub search.
