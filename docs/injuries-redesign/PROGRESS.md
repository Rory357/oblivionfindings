## §0 LOCKED decisions (do not relitigate)

1. **Canonical lifecycle (5 statuses):** `reported → under_treatment → return_to_work → recovered → closed`. The old UI `open/active/recovering/returned_to_work` is WRONG — replace everywhere. Migration default `active`→`reported`; **remove dead `WorkplaceInjury::scopeActive()`** (status='active' never written, zero callers).
2. **Reuse, do not duplicate.** All 9 controller endpoints already work — wire modals to their EXACT field names (captured below). Reuse `WorkplaceInjuryObserver` (HsEvent + Control Room bridge) as-is. Reuse shared kits + the shared `AttachmentUploader`.
3. **No new permissions.** Read = `hazards.view`, write = `hazards.manage` (create also accepts `hazards.create`). Add a `can.hazards.manage` flag to `HandleInertiaRequests` (additive) for client gating.
4. **Modals = Add-Client parity.** Build `InjuryWizardDialog` + `InjuryDetailDialog` + action sub-modals on `@/components/wizard/shell` (`WizardShell`) + `@/components/wizard/primitives`. Detail modal is **WizardShell-based** (rail = sections), NOT a bespoke gradient modal.
5. **Detail-over-list** like Events: row click → `router.get(..., {injury:id}, {only:['detail'], preserveState, preserveScroll})`; close drops `?injury=`. `buildInjuryDetail()` is the single shared payload (mirror the TS type 1:1). Retire `create.tsx`/`show.tsx`; `show()` → redirect to `index?injury={id}` (keeps "Open full page").
6. **Lifecycle transitions:** add explicit `POST /health-safety/injuries/{injury}/status` (validates allowed transition + sets derived dates e.g. `actual_return_date` on recovered) rather than overloading `update`. Gate context-menu/footer actions on `can.manage` AND status.
7. **Premium document upload:** add the standard per-module attachment stack (NOT polymorphic) reusing `AttachmentUploader` (`resources/js/components/ui/file-dropzone.tsx`). New `workplace_injury_attachments` table + `WorkplaceInjuryAttachment` model + `attachments()` relation + IDOR-safe store/download/destroy (copy `SafeguardingAttachmentController`). `kind` = `medical_cert|acc_form|rtw_clearance|photo|document`. disk `public`, max 10 MB, short index name `wia_injury_idx`.
8. **HR seam:** give the dialog + rows an `embedded`/`readOnly` mode (no write affordances) — but do NOT wire it into the staff profile page (README §7: leave the seam only).

## §1 EXACT endpoint signatures (wire modals to these — no signature change)

- `POST /health-safety/injuries` (store): user_id, site_id, injury_date, injury_type(15-enum), body_part_affected, severity(minor/moderate/serious/critical), description, medical_treatment_type(8-enum), immediate_treatment?, worksafe_notifiable(bool), acc_claim_number?, notes?. Sets status='reported', lost_time_days=0. `stay` bool → Save-&-add-another. **EXTEND: accept related_incident_id + acc_claim_lodged (+ _modal flow + flash created id).**
- `PUT /health-safety/injuries/{injury}` (update, all `sometimes`): status, lost_time_days, expected_return_date, actual_return_date, acc_claim_number, acc_claim_lodged, worksafe_notifiable, notes. **EXTEND: related_incident_id, body_part_affected/severity/etc for edit-mode wizard.**
- `POST /health-safety/injuries/{injury}/rtw-plans` (storeRtwPlan): plan_start_date, plan_end_date?, goals=string[], stages[]={name,start_date,end_date?,hours_per_week?(0-60),duties_description?}, medical_clearance_notes?, medical_clearance_provider?, worker_id?, manager_id?. Sets status='active'.
- `PUT /health-safety/injuries/rtw-plans/{rtwPlan}` (updateRtwPlan): sometimes variants + status(active/in_progress/completed/cancelled) + review_notes?.
- `POST /health-safety/injuries/{injury}/capacity-assessments` (storeCapacityAssessment): assessment_date, **user_id**(assessor), assessor_name?, assessor_type(gp/specialist/physiotherapist/occupational_therapist/employer), capacity_status(fit_for_full_duties/fit_for_modified_duties/unfit_for_work/requires_review), restrictions?, recommendations?, next_assessment_date?, assessment_summary?. **document_path exists but unwired.**
- `POST /health-safety/injuries/rtw-plans/{rtwPlan}/modified-duties` (storeModifiedDuty): start_date, end_date?, **modified_duties_description**, **hours_per_day**(0-24), restrictions?, accommodations?, user_id?. Keyed by PLAN.

DB NOT-NULL vs controller-nullable mismatches to fix: `modified_duties.restrictions` (NN in migration, nullable in rules) and `work_capacity_assessments.assessor_name` (NN in migration, nullable in rules) → make both nullable.
