# Stock workspace completion and release checks

This pass replaces the remaining unbounded desktop stock views and checks the release candidate. It does not migrate, enable or deploy production. The separate Workforce work is outside this branch.

## Implementation

- Stock, pharmacy orders and the retained controlled-stock view share compact Rory tables, with 10 rows per page by default and optional 25 or 50. Order details retain all five stage dates, quantities, batch, expiry and permitted next actions. Kebab and right-click menus use the same actions.
- Pagination and search now operate on scoped database queries. Pharmacy history is no longer capped at the newest 40 orders. Header totals describe the full permitted person/house scope. Closed, cancelled and short-closed orders do not inflate open-order alerts.
- A complete thin medicine picker remains available. Detailed stock/pack history is loaded for bounded page/action contexts; selecting another medicine loads its own scoped context. Rapid searches and scope changes cancel older requests, and a failed request offers retry without presenting old rows as new results.
- Unknown balances remain unknown. A controlled count cannot invent a zero starting balance, and absence of a discrepancy alone cannot claim a witnessed reconciliation. Selecting a different medicine clears previously entered count and witness evidence.
- Builds retain earlier immutable hashed scripts so an already-open tab can still load them. This addresses the documented deleted-chunk failure during an in-place rebuild. It is not an atomic release publisher; automatic asset pruning is intentionally unset until an appropriate open-tab/cache retention period is defined.
